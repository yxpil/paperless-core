# 10 视频会议、录播与 AI 总结

## 10.1 三条路线，成本差三倍

| 路线 | 适用 | 优点 | 代价 |
| --- | --- | --- | --- |
| 自建 SFU | 无既有视频系统、要求私有化 | 数据不出域、可深度集成 | 带宽与运维成本高，弱网优化要自己做 |
| 对接既有 | 客户已有华为/科达/腾讯会议 | 复用客户投资，上线快 | 受制于对方 API，UI 割裂 |
| 混合 | 大会议室用硬件终端，小会场用自建 | 兼顾体验与成本 | 复杂度最高，需统一会控 |

建议：**首版做「对接既有 + 自建轻量 SFU 双通道」**。会议里只允许一种视频源生效，避免回声与重复画面；切换由主持人控制。

## 10.2 自建 SFU 设计

| 项 | 设计 |
| --- | --- |
| 协议 | WebRTC（SVC / Simulcast），H.264 与 AV1 可选 |
| 拓扑 | 每节点承载 ≤ 500 路，按 roomId 分片 |
| 弱网 | 三层：FEC、Jitter Buffer、按丢包切层（L1/L2/L3） |
| 穿透 | STUN 自建 + TURN 集群（UDP 3478 / TLS 5349） |
| 混流 | 服务端混流用于录播与 TV 端，避免 TV 端收 9 路 |
| 音频 | Opus 48 kHz，回声消除在客户端，服务端只做混音 |

关键取舍：**默认不自建 MCU 混流给终端**，混流只用于录制与只读大屏。原因是混流会牺牲灵活布局，且服务端 CPU 成本高。终端能自己合成的，就让终端合成。

## 10.3 录播

| 模式 | 说明 | 适用 |
| --- | --- | --- |
| 房间录制 | 录混流后的画面（含共享内容） | 常规会议存档 |
| 多流录制 | 每路单独存，会后可重排 | 需要个性化回放 |
| 只录共享 | 只录屏幕与音频，不录人脸 | 隐私敏感场景 |
| 分段录制 | 每 10 分钟一段，断点续录 | 长会议、防丢 |

存储与安全：

- 录制文件按「租户/部门/会议」三级目录，文件名不含议题（防泄露）。
- 落盘即加密（AES-256-GCM 或 SM4-GCM），密钥由 KMS 按部门 DEK 派生。
- 回放需授权，默认有效期 30 天，可延长；回放带动态水印。
- 录制状态与时长写入会议事件，可被审计。

## 10.4 AI 会议总结

AI 总结最容易做成「看起来很智能但没人用」。原因是只做摘要，不做**可执行结论**。平台的做法是把输出固定为六段结构：

| 段落 | 内容 | 来源 |
| --- | --- | --- |
| 会议概览 | 时间、参会、议题 | 元数据 |
| 议题与讨论 | 每个议题的观点聚类 | ASR + 分段 |
| 分歧点 | 明确对立观点，标注发言人 | 语义分析 |
| 决议 | 形成的结论，逐条编号 | 主持人确认 |
| 待办 | 事项、责任人、时限 | 决议抽取 |
| 风险与遗留 | 未决事项、需上级决定的事项 | 规则 + 模型 |

处理流水线：

```mermaid
flowchart LR
  A[音频流] --> B[ASR 转写<br/>流式 + 热词]
  B --> C[说话人分离<br/>声纹 + 座位先验]
  C --> D[议题分段<br/>议程对齐 + 语义切分]
  D --> E[摘要生成<br/>分块摘要 + 全局归并]
  E --> F[决议与待办抽取<br/>结构化约束]
  F --> G[人工校对<br/>主持人确认后签发]
```

四个工程要点：

1. **热词表**：会前从材料标题、参会人姓名、部门名生成热词，ASR 准确率可提升 5–10 个百分点。
2. **议程对齐**：把转写文本对齐到议程条目，摘要才不会跑题。没有议程的会议，按静默间隔切分。
3. **结构化约束**：决议必须带「动作 + 对象 + 责任人 + 时限」，缺一项就标为「待确认」，不允许模型自由发挥。
4. **人工确认**：AI 产出的是草稿，必须由主持人确认后才成为正式纪要。这一条既是质量控制，也是责任划分。

成本控制：ASR 按时长计费，摘要按 token 计费。平台按「会议重要度」分级处理：普通会议只做转写与关键句抽取，重要会议才做全量摘要。默认策略可在租户级配置。

## 10.5 与会议状态机的集成

| 会议状态 | 视频 | 录制 | AI |
| --- | --- | --- | --- |
| DRAFT | 关 | 关 | 关 |
| READY | 可预连接（候场） | 关 | 预加载模型与热词 |
| LIVE | 开 | 按策略开 | 流式转写 |
| PAUSED | 视频保持，录制暂停 | 暂停 | 暂停 |
| CLOSED | 关 | 停止并落盘 | 生成草稿 |
| ARCHIVED | — | 只读 | 只读 |

## 10.6 指标

| 指标 | 目标 |
| --- | --- |
| 端到端视频延迟 | ≤ 400 ms（同城） |
| 首帧 | ≤ 1.5 s |
| 20 方会议服务端 CPU | ≤ 40%（8 核节点） |
| 录制丢帧率 | ≤ 0.1% |
| ASR 字准 | ≥ 92%（普通话、安静环境） |
| 纪要草稿生成 | 会后 ≤ 30 分钟 |

## 10.7 隐私与合规

视频与语音属于个人信息，处理必须满足三条：会前明示（会议邀请中写明将录制与转写）、会中可见（录制指示灯与提示条）、会后可控（删除申请通道与保留期限）。缺任一条，方案在合规审查时就会被否。
