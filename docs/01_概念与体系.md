# 01 概念与体系

## 1.1 定义

无纸化常被误认为「把纸换成屏幕」。真正的无纸化是**信息流的载体替换 + 流转方式的权限化 + 过程数据的资产化**。本平台把它拆成三层，缺一层就不成立。

| 层次 | 定义 | 判定标准 | 缺失后的表现 |
| --- | --- | --- | --- |
| 载体无纸 | 材料以电子对象存在，不产生纸质副本 | 从起草到归档全程无打印环节 | 会上仍打印，屏幕只是投影 |
| 过程无纸 | 分发、批注、表决、决议、归档全部在线完成 | 每个环节都有系统事件，不靠人工回填 | 签到表、表决票仍是纸 |
| 决策无纸 | 决议、任务、责任、时限进入可跟踪体系 | 决议能追踪到完成状态 | 纪要写完就进抽屉 |

「协同」在此基础上再加三度：

- **端协同**：同一个人在不同设备上看到的是同一份状态，不是三份副本。
- **人协同**：多人对同一对象并发操作，系统给出确定的合并结果，而不是「你改你的我改我的」。
- **组织协同**：跨部门、跨企业、跨网段共享同一份材料，权限随组织关系自动收敛。

因此，**协同无纸化 = 单一事实来源 + 多端实时投影 + 跨组织权限流转 + 全过程可溯源**。这四件事构成平台的技术内核，其余功能都是它们的外围组合。

## 1.2 与相邻系统的边界

很多项目失败在边界不清：把无纸化做成网盘，或做成视频会议。边界必须写死。

| 系统 | 它擅长 | 本平台与它的关系 | 不允许的越界 |
| --- | --- | --- | --- |
| OA | 流程审批、公文流转 | 通过 API 桥接交换会议与决议数据 | 不替代 OA 的审批引擎 |
| 视频会议 | 多方音视频 | 内建轻量 SFU，同时可对接既有 MCU | 不追求替代专业视频会议的全场景 |
| 企业网盘 | 文件存储与共享 | 作为 NAS 连接器的一种被接入 | 不做通用网盘的文件同步盘 |
| 档案系统 | 长期归档与编目 | 归档时推送元数据与包 | 不替代档案系统的编目规则 |
| 会议硬件系统 | 话筒、升降、桌牌 | 通过协议网关纳管 | 不做硬件固件研发 |

边界的意义在于：本平台只对「会议与协作过程中的对象状态」负责，对象最终沉淀到哪里，由档案系统负责。

## 1.3 能力地图

平台能力按六个域组织，每个域对内是一个插件组，对外是一组可独立售卖的能力包。这种划分直接对应第 14 章的行业 DIY：医院买 A+B 域，学校买 A+C 域。

| 域 | 能力 | 章节 |
| --- | --- | --- |
| 会议域 | 建会、议程、材料、同屏、批注、表决、纪要、分组、主持 | 03、05、08 |
| 协作域 | 文档协同、标记同步、白板、任务、评论 | 08 |
| 知识域 | 检索、联邦查询、Excel/MySQL 索引、溯源 | 09 |
| 媒体域 | 视频会议、录播、投屏、AI 总结 | 05、10 |
| 治理域 | 身份、权限、加密、密钥、审计、时间戳、危险感知 | 07、09、11 |
| 集成域 | 插件、API 桥接、财务、传统系统、DDNS/穿透 | 04、06、13、15 |

## 1.4 价值度量

无纸化项目最常见的争议是「省了多少钱」说不清。平台在立项时就把度量口径固化，验收时按同一口径复核。

| 指标 | 纸质基线（100 人 / 月 30 场 / 每场 60 页） | 平台目标 | 采集方式 |
| --- | --- | --- | --- |
| 单场印制成本 | 60 页 × 100 份 + 装订 | 归零（保留 1 份存档） | 财务对比 |
| 会前分发耗时 | 2 小时至 1 个工作日 | 3 分钟内完成推送预载 | 系统时间戳 |
| 材料改版响应 | 重新打印约 40 分钟 | 30 秒内全端生效 | 版本事件 |
| 纪要成稿 | 4 小时至 2 个工作日 | 会后 30 分钟出初稿 | 纪要签发时间 |
| 决议闭环率 | 无统计 | 可统计，目标 85% 以上 | 任务完成率 |

## 1.5 术语

| 术语 | 含义 |
| --- | --- |
| 对象（Object） | 平台中一切可寻址的实体：会议、材料、页、批注、笔迹、决议、插件实例 |
| rev | 房间或文档的单调递增版本号，一切同步与溯源的锚点 |
| 能力令牌（Capability Token） | 短期、限定范围、可撤销的授权凭证，替代长期密钥 |
| 插件（Plugin） | 以 manifest 声明能力、在沙箱中运行的功能单元 |
| 内置插件 | 官方维护、默认安装的插件，与第三方插件同构，不允许有绕过沙箱的后门 |
| 联邦（Federation） | 多个独立部署的节点交换数据但不共享数据库 |
| 联盟节点 | 参与联邦协作的独立组织节点，可跨网段、跨企业 |
| 追踪链（Trace Chain） | 一个对象从创建到当前状态的全部事件哈希链 |
| 影子双写 | 对接老系统时，先写老系统再写新系统，比对差异后再切换 |

## 1.6 三条容易被忽略的判断

**第一条：无纸化的核心资产是过程数据，不是材料本身。** 材料在会后往往进档案系统，真正长期有价值的是「谁在什么议题上表达了什么、形成了什么决议」。因此平台把过程事件当作一级公民存储与索引，而不是日志。

**第二条：多端不是多版本。** 一旦允许终端各自保存可写副本，就必然出现「平板上的版本和 PC 上的不一样」。平台因此禁止终端持有可写状态，终端只缓存只读渲染结果与待提交队列。

**第三条：跨组织协作的难点是权限而不是网络。** 打洞、穿透、DDNS 都是通道问题，工程上可解；真正难的是「A 企业的部门文档给 B 企业的项目组看三个月，到期自动收回，且 B 企业不能转发」。平台用「委托授权 + 到期回收 + 水印追责」三件套解决，见 08 章第 8.7 节。
