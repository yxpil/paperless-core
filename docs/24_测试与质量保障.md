# 24 测试与质量保障

## 24.0 质量不是测出来的

把质量寄托在「最后测一遍」的系统，缺陷成本会以十倍级上升：需求阶段发现 1，开发阶段 10，测试阶段 100，上线后 1000。因此本章的顺序是：先定义什么叫「做完了」，再谈怎么测。

本项目有三类缺陷特别贵：**同步错位**（各端画面不一致）、**权限越界**（不该看的人看到了）、**数据错乱**（表决结果、审计链）。这三类不能只靠用例覆盖，必须靠机制（rev、能力令牌、哈希链）+ 专项测试双保险。

> 分工说明：**本章讲方法与标准**（分层、用例设计方法、指标、混沌、准出）；**逐功能的可执行用例在 `30_全功能测试用例清单.md`**（332 条，25 个模块，含优先级与自动化标记）；**用例如何组成集合、何时执行、失败怎么办在 `31_测试集合规划与执行.md`**（21 个集合）。三章不重复，改用例动 30，改编排动 31，改方法动本章。

## 24.1 测试分层

| 层 | 范围 | 数量占比 | 单次时长 | 责任 |
| --- | --- | --- | --- | --- |
| 单元 | 领域逻辑、算法、状态机 | 60% | 毫秒级 | 开发 |
| 集成 | 仓储、模块间、外部依赖替身 | 25% | 秒级 | 开发 |
| 契约 | 六端与后端、插件与内核 | 5% | 秒级 | 开发 + 测试 |
| 端到端 | 完整会议流程 | 8% | 分钟级 | 测试 |
| 验收 | 客户场景与清单 | 2% | 小时级 | 测试 + 客户 |

比例不是教条，但**倒金字塔（大量 E2E、少量单元）一定会慢且脆**。E2E 超过 15% 的项目，CI 通常跑不完。

## 24.2 用例设计

### 24.2.1 六种方法，各管一类问题

| 方法 | 管什么 | 本项目用法 |
| --- | --- | --- |
| 等价类 | 输入域划分 | 密级、文件大小、页数、参会人数 |
| 边界值 | 临界点 | 200 终端、2000 条补拉窗口、500 MB 文件 |
| 状态迁移 | 状态机 | 会议 7 状态、插件 6 状态 |
| 场景法 | 端到端流程 | 建会→上传→开局→表决→闭会→归档 |
| 正交表 | 多因素组合 | 端 × 权限 × 密级 × 网络 |
| 错误推测 | 经验盲区 | 时钟跳变、重复提交、中途换设备 |

### 24.2.2 必测清单

| 域 | 必测点 | 判据 |
| --- | --- | --- |
| 会议状态 | 每个合法迁移 + 每个非法迁移 | 非法迁移一律拒绝且不改变状态 |
| 权限 | 角色 × 密级 × 组织域 矩阵全组合 | 越权访问 100% 被拒，且记审计 |
| 同步 | 断线、跳号、快照、并发翻页 | rev 连续，无重复应用 |
| 材料 | 20 种格式转帧、损坏文件、超大文件 | 成功率 ≥ 98%，失败有明确原因 |
| 批注 | 跨版本迁移、锚点失效、并发删除 | 不丢批注，失效标「待确认」 |
| 表决 | 重复提交、离线补传、匿名 | 明细唯一，结果可由明细重算 |
| 设备 | 注册、离线、指令超时 | 失败可重试，不阻塞会议 |
| 检索 | 多库、权限裁剪、溯源 | 结果不越权，来源可追 |
| 审计 | 链完整性、时间戳、断链恢复 | 可离线验签 |

## 24.3 自动化

| 要素 | 要求 |
| --- | --- |
| 数据工厂 | 一键生成租户/组织/会议/材料，测试不依赖人工造数 |
| 环境 | 每 PR 起独立命名空间，用完销毁 |
| 稳定性 | 禁止 `sleep`，用条件等待；失败留存 trace 与截图 |
| 可读性 | 用例名说清「在什么条件下做什么、期望什么」 |
| 选择执行 | 按改动范围选跑，全量每晚跑 |

自动化率目标：单元覆盖核心模块 ≥ 80%，P0 用例自动化 ≥ 90%。但**自动化率不是考核指标**，因为它可以被低价值用例刷高。

## 24.4 性能与容量

| 场景 | 配置 | 通过标准 |
| --- | --- | --- |
| 容量 | 500 场会议 / 20000 连接 / 2 小时 | 错误率 ≤ 0.1%，同步 P95 ≤ 300 ms |
| 尖峰 | 10 分钟内 200 场同时开局 | 无雪崩，排队可见 |
| 长稳 | 单场 200 终端 / 8 小时 | 内存无持续增长，无连接泄漏 |
| 大文件 | 300 页 PPT / 200 MB Excel | 转帧 ≤ 5 分钟，首屏 ≤ 1 秒 |
| 检索 | 1000 万文档 | 查询 P95 ≤ 500 ms |
| 审计 | 5000 条/秒写入 | 无丢链，锚定不延迟 |

压测必须做瓶颈定位，不能只报「TPS 多少」。标准输出是：瓶颈在哪一层、到什么量级出现、扩容几个节点可解。

## 24.6 安全测试

| 项 | 方法 | 通过标准 |
| --- | --- | --- |
| 越权 | 权限矩阵全组合 | 0 例成功越权 |
| 注入 | SQL/命令/模板 | 0 例 |
| 文件 | 恶意文件、超大文件、压缩炸弹 | 全部拦截或安全失败 |
| 会话 | 令牌重放、固定、越权刷新 | 全部拒绝 |
| 加密 | 密钥使用、明文残留 | 内存与磁盘无明文 |
| 审计 | 篡改、删除、断链 | 可检测且告警 |
| 渗透 | 第三方或红队 | 高危 0，中危有处置 |

越权测试要覆盖「合法的低权限用户尝试高权限操作」，而不只是「未登录用户」。前者才是真实风险。

## 24.7 缺陷管理

| 级别 | 定义 | 准出 |
| --- | --- | --- |
| P1 | 会议无法进行 / 数据错误 / 安全漏洞 | 0 |
| P2 | 主功能不可用但有规避 | ≤ 3 且有计划 |
| P3 | 次要功能 / 体验 | ≤ 15，纳入下版 |
| P4 | 文案 / 样式 | 可带入 |

逃逸分析：每个上线后发现的缺陷都要回答「为什么测试没发现」。答案只有四类：用例缺失、环境差异、数据差异、设计未定义。前两类补用例与环境，后两类回到需求与设计修根因。

## 24.8 混沌与故障注入

| 注入 | 期望行为 |
| --- | --- |
| 断网 30 秒 | 终端进入离线，恢复后按 lastRev 追平 |
| 杀 sync-worker | 备节点接管，会议不中断，rev 不跳号 |
| 主库延迟 30 秒 | 读降级到备库，写排队，界面提示 |
| 磁盘变慢（IO 延迟 10 倍） | 转帧降速但不失败，队列可见 |
| 时钟跳变 +5 分钟 | 审计链仍可验证，时间戳标注异常 |
| 证书过期 | 拒连并告警，不用「继续访问」 |
| 依赖系统宕机 | 熔断打开，降级路径生效，审计记录 |

混沌演练每月一次，在预生产做，不在生产做（除非有明确窗口与回滚方案）。

## 24.9 准出与验收

准出四条件：P1 为 0、P2 达标、关键指标达标、文档与契约同步。缺一不发。

验收按第 05 章验收清单逐条执行：功能 P0 100%、性能三场景达标、安全高危 0、兼容矩阵全覆盖、运维演练通过、培训完成。

## 24.10 质量指标

| 指标 | 目标 |
| --- | --- |
| 缺陷密度 | ≤ 2 个/千行 |
| 缺陷逃逸率 | ≤ 5% |
| 用例有效率 | ≥ 70%（能发现缺陷的比例） |
| 自动化执行时长 | PR 段 ≤ 10 分钟 |
| 回归通过率 | ≥ 98% |
| 线上 P1 数 | 0 |

「用例有效率」常被忽略：写了 5000 条用例但从不发现缺陷，说明用例在验证「已知能通过的事」。
