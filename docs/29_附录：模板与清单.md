# 29 附录：模板与清单

> 本章是可直接复制使用的模板集。模板的作用不是形式，是**强制回答那些总被跳过的问题**。

## 29.1 ADR（架构决策记录）

```markdown
# ADR-0xx 标题

- 状态：提议 / 已接受 / 已取代（被 ADR-0yy 取代）/ 已废弃
- 日期：YYYY-MM-DD
- 决策人：xxx
- 关联需求：FR-xxx / 无

## 背景
为什么现在必须做这个决定？不做的后果是什么？

## 选项
| 选项 | 优点 | 代价 | 风险 |
| A | | | |
| B | | | |

## 决定
选哪个，一句话说清。不含"再评估"。

## 代价与约束
接受什么损失、留下什么约束、什么条件下需要推翻。

## 复审时间
YYYY-MM 或触发条件（如"连接数超过 5 万时"）
```

## 29.2 PR 模板

```markdown
## 变更内容
一句话说明做了什么。

## 关联
需求：FR-xxx ｜ 缺陷：BUG-xxx ｜ ADR：ADR-0xx

## 影响面
- [ ] 触及内核 API
- [ ] 触及 contracts
- [ ] 触及数据库结构（是否 expand-contract 分步）
- [ ] 触及权限判定
- [ ] 需要新配置项 / 新密钥

## 验证
- [ ] 单测 / 集成测试
- [ ] 手动验证步骤（写出步骤，不写"已验证"）
- [ ] 回滚方式

## 自查
- [ ] 无裸色值 / 无硬编码租户名
- [ ] 日志不含敏感信息
- [ ] 有降级路径
```

## 29.3 变更申请单

```markdown
# 变更单 CHG-YYYYMMDD-xx

- 提出人 / 日期：
- 关联需求：FR-xxx
- 变更类型：澄清 / 小变更 / 大变更 / 紧急

## 变更内容
（具体到可执行的动作，不写"优化体验"）

## 影响分析
| 维度 | 影响 |
| 进度 | 增加 x 人日，影响里程碑 Gx |
| 范围 | 替换 FR-0yy / 推迟到 P2 |
| 技术 | 是否触及内核、契约、库结构 |
| 风险 | 引入什么新风险 |

## 替换或推迟方案
必填。没有这一栏不予审批。

## 决策
批准 / 拒绝 / 调整后批准 ｜ 决策人 ｜ 日期
```

## 29.4 事故报告

```markdown
# INC-YYYYMMDD-xx

## 概要
- 影响范围：租户 / 会议室 / 终端数 / 时长
- 级别：P1 / P2 / P3
- 发现方式：监控告警 / 用户报障 / 巡检

## 时间线
| 时间 | 事件 |
| T0 | 首次异常 |
| T+5 | 告警触发 |
| T+15 | 响应 |
| T+40 | 恢复 |

## 根因
技术根因 + 流程根因（为什么没提前发现）

## 处置
做了什么、是否回滚、是否触发熔断

## 改进项
| 改进 | 责任人 | 截止 | 验证方式 |
```

## 29.8 插件上架检查单

| # | 检查 | 判据 |
| --- | --- | --- |
| 1 | manifest 完整 | id/version/type/contractVersion 齐全 |
| 2 | 能力已登记 | 每个 capability 在 contracts 有 schema |
| 3 | 权限最小 | 未声明即拒绝，无通配 |
| 4 | 资源上限 | cpu/memory/timeout 已设 |
| 5 | 卸载清理 | 命名空间数据可清空 |
| 6 | 健康检查 | 失败可降级，不影响主流程 |
| 7 | 出网白名单 | 域名逐条列出 |
| 8 | 签名 | 包签名可验证 |
| 9 | 文档 | 含安装、配置、卸载、排障 |
