## 0.2 一句话架构

**微内核 + 插件 + 六端共享内核 + 联邦存储 + 分布式账本式溯源。**

内核只做五件事：身份与权限、会话与版本（rev）、对象存储与加密、事件总线、审计与时间戳。其余一切能力（会议、文档、视频、投屏、检索、财务、行业模板）都是插件。这样做的直接收益是：医院要的病历水印、学校要的教室分组、企业要的财务对账，都不需要改内核，也不需要为每个客户维护一个分支。

## 0.3 五条不可动摇的原则

1. **状态在服务端，终端只呈现**。六端不互传文件，只同步事件。
2. **所有可写对象都有版本与责任人**。没有版本号的对象不允许存在。
3. **所有跨域访问都走能力令牌**。插件、外部系统、终端都不持有长期密钥。
4. **所有关键动作都可溯源**。溯源不是日志，是「谁、在什么时间、对哪个对象、做了什么、依据什么授权」的可验证链。
5. **降级优先于报错**。任何能力缺失都必须有可用的低配路径，而不是让会议开不下去。

## 0.4 与基线文档的差异

| 基线（第一轮 DOCX） | v2.0 调整 | 原因 |
| --- | --- | --- |
| 业务模块直接写在 NestJS 里 | 改为内核 + 插件，业务模块降级为「内置插件」 | 支撑行业 DIY 与私有定制 |
| 单一 PostgreSQL | 元数据 PG + 业务库 MySQL 联邦 + 检索 ES | 对接既有业务系统与多库合一 |
| 同屏只做文档级 | 文档级为主，视频级（SFU）为辅，二者统一在一个投屏会话里 | 需要支持第三方应用与远程控制 |
| 审计写本库 | 本库 + 哈希链 + 外部时间戳 + 可推送审计服务器 | 满足可验证溯源 |
| 单集群部署 | 控制面/数据面分离，支持主备、双活、联盟节点 | 支撑跨网段与多组织协作 |
