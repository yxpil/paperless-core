# 28 实施、培训与运营移交

## 28.1 六个阶段

| 阶段 | 目标 | 关键交付 | 典型工期 |
| --- | --- | --- | --- |
| 勘察 | 搞清现场真实条件 | 勘察报告、风险清单 | 3–5 天 |
| 设计 | 确定部署与接入方案 | 实施方案、配置清单 | 3 天 |
| 部署 | 环境可用 | 部署记录、冒烟结果 | 2–3 天 |
| 试点 | 真实会议验证 | 试点记录、问题清单 | 1–2 周 |
| 推广 | 分批覆盖 | 开通记录、培训签到 | 按规模 |
| 移交 | 客户自主运营 | 移交清单、验收报告 | 3 天 |

工期能否兑现，九成取决于勘察。勘察不足的项目，后面每一步都在返工。

## 28.2 勘察清单

| 类别 | 检查项 | 判据 |
| --- | --- | --- |
| 网络 | 出口带宽、跨网段策略、NAT 类型、是否隔离网 | 实测而非询问 |
| 会议室 | 终端数量、老设备型号、投屏方式、供电与 PoE | 逐间登记 |
| 既有系统 | OA/ERP/HIS/NAS/旧会议系统 | 接口是否开放 |
| 账号 | 是否有统一身份源（AD/LDAP/SSO） | 可对接则省 30% 实施量 |
| 安全 | 密级、等保级别、是否密评 | 决定加密与网络方案 |
| 运维 | 客户是否有运维团队、值班安排 | 决定移交深度 |

勘察必须「实测」。客户说「我们带宽千兆」，实际会议室到弱电间可能是百兆共享，这种落差在试点第一场就会暴露。

## 28.3 上线切换

| 方案 | 做法 | 适用 | 风险 |
| --- | --- | --- | --- |
| 并行 | 新旧同时可用，逐步迁移 | 重要单位 | 双份维护 |
| 直接切换 | 停旧启新 | 小型、无历史包袱 | 无回退缓冲 |
| 分批 | 按楼层/部门推进 | 大型单位 | 周期长 |

无论哪种方案，必须准备回退路径：源系统只读保留 30 天，切换失败可回切。没有回退的切换方案不予批准。

切换当天的三件事：值班表、通信群、回退决策人。三件缺一，现场就会乱。

## 28.4 培训体系

| 对象 | 内容 | 时长 | 考核 |
| --- | --- | --- | --- |
| 系统管理员 | 组织与权限、策略、插件、审计 | 2 天 | 实操通过 |
| 会议主持人 | 建会、开局、控场、表决、闭会 | 半天 | 模拟会议 |
| 参会人 | 阅读、批注、签到、表决 | 1 小时 | 无需 |
| 终端运维 | 终端部署、故障排查、备件更换 | 1 天 | 实操通过 |
| 安全管理员 | 密钥、审计导出、应急 | 半天 | 演练通过 |

培训不看签到率，看**首次独立操作成功率**。主持人培训后仍需要实施人员在场，说明培训没做到位。

## 28.5 运营指标

| 指标 | 口径 | 目标 |
| --- | --- | --- |
| 会议成功率 | 正常闭会 / 计划会议 | ≥ 99% |
| 就绪率 | 会前 15 分钟全部终端就绪 | 100% |
| 首次入会时长 | 扫码/登录到待机页 | ≤ 8 秒 |
| 工单量 | 每百场会议工单数 | ≤ 3 |
| 故障恢复 | 从报障到恢复 | P1 ≤ 2 小时 |
| 用户活跃 | 月活主持人占比 | ≥ 70% |

「工单量」比「满意度」更可信：满意度调查会被礼貌性打分，工单量不会。

## 28.6 移交清单

| 类别 | 内容 |
| --- | --- |
| 文档 | 部署手册、运维手册、应急预案、本套设计文档 |
| 账号 | 管理员账号、只读审计账号（密钥单独交接） |
| 密钥 | KMS 管理员、备份分片保管人 |
| 监控 | 看板地址、告警通道、值班表 |
| 资产 | 服务器、网关、终端台账与序列号 |
| 合同 | 维保范围、响应时限、升级方式 |

移交必须有签字。签字意味着责任转移，没有签字的移交只是「口头说过了」。

## 28.7 持续运营

| 节奏 | 动作 |
| --- | --- |
| 每周 | 巡检（容量、告警、备份） |
| 每月 | 运营报告（会议量、故障、工单） |
| 每季 | 客户回顾会（问题、需求、改进） |
| 每半年 | 版本升级 + 演练 |

季度回顾会的价值不在汇报，在**把现场问题变成需求池里的编号**。没有这个通道，客户的不满会在续约时才爆发。

## 28.8 实施常见风险

| 风险 | 表现 | 缓解 |
| --- | --- | --- |
| 网络未改造 | 会议室 AP 不足，200 台终端连不上 | 勘察阶段出具网络整改清单 |
| 老设备比例高 | 试点时大量设备不可接入 | 提前出兼容清单，写进合同 |
| 客户配合度低 | 组织数据不全，账号开不出来 | 明确对接人与时间点 |
| 会议室改造延期 | 屏、线、电未就位 | 与基建方排期对齐 |
| 期望错位 | 客户以为「什么都能接」 | 立项时用「不做清单」管理预期 |

最后一条最关键：实施失败多半不是技术问题，是期望管理问题。**明确写清「不能做什么」，比承诺「都能做」更能保住项目**。
