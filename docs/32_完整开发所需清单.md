# 32 完整开发所需清单

## 32.0 文档给了什么，还缺什么

前 31 章解决的是**设计问题**：系统长什么样、怎么分层、怎么测、怎么发。真正开工还缺四类东西：**人、环境、资格、素材**。这四类缺任何一项，代码写出来也跑不成产品。

本章只列「必须准备的东西」和「不准备的后果」，不重复设计内容。

## 32.1 人

### 编制（8 人起步，对应 18 章 87 人月）

| 角色 | 人数 | 关键能力（缺了就做不成） | 何时到位 |
| --- | --- | --- | --- |
| 架构／技术负责人 | 1 | 能守住内核边界，敢对需求说「这个进插件」 | 第 0 月 |
| 服务端（Node/TS） | 2 | 分布式会话、事件定序、PG 事务边界 | 第 0 月 |
| 前端（React + Electron） | 2 | 六端差异、渲染性能、Canvas 绘制 | 第 1 月 |
| 音视频／媒体 | 1 | WebRTC、转帧、录制、SVC | 第 2 月 |
| 测试／质量 | 1 | 能写自动化，不是只会点页面 | 第 1 月 |
| 运维／安全 | 1 | K8s、证书、密钥、审计 | 第 1 月 |
| 产品／需求 | 1 | 能把客户口语翻成可验收条目 | 第 0 月 |
| UI／交互 | 0.5–1 | 设计令牌、六端一致性、无障碍 | 第 0 月 |

**不可替代的两个岗**：架构负责人与音视频工程师。这两个岗中途换人，等于重来半年。

### 外部资源

| 需求 | 说明 | 周期 |
| --- | --- | --- |
| 渗透测试 | 每季一次，第三方执行 | 2 周出报告 |
| 等保测评 | 有资质机构，二级或三级 | 1–3 个月 |
| 密评 | 涉密或国密场景必须 | 2–3 个月 |
| 老设备协议适配 | 按厂商买文档或找原厂支持 | 视厂商 |
| 真机运维 | 17 台设备要有人管固件与备件 | 常设 |

## 32.2 环境（四套，不能合并）

| 环境 | 用途 | 规模 | 硬约束 |
| --- | --- | --- | --- |
| 开发 | 本地起全栈（compose） | 每人 16 GB 内存起 | 一键起，不依赖公网 |
| 测试 | 功能回归 + 真机联调 | 1 应用 + 1 库 + 1 存储 | 数据每日重置 |
| 预发 | 压测、混沌、发布验证 | 与生产同构但小一号 | 独立域名与证书 |
| 生产 | 交付 | 按 03 章三档 | 不与演示共用 |

生产与预发**必须同构**，否则「预发过了线上挂了」会变成常态。演示环境可以省，但绝不能拿生产当演示。

### 服务器最低清单（标准档）

| 用途 | 规格 | 数量 |
| --- | --- | --- |
| 应用节点（api/ws/sync-worker） | 8C16G | 3 |
| 媒体节点（doc-worker/media-worker） | 16C32G + GPU 可选 | 2 |
| 数据库 | 16C64G + SSD | 1 主 1 备 |
| Redis | 8C16G | 3（哨兵） |
| 对象存储 | 4TB 起 | 1 集群 |
| 消息（NATS） | 4C8G | 3 |
| 检索（OpenSearch） | 16C32G + SSD | 3 |
| 网关／边缘 | ARM64 四核 2 GB 双网口 | 每会议室 0–1 |

带宽：单房间 200 终端同屏按 03 章估算，**出口按并发房间 × 峰值累加，至少留 2 倍余量**。带宽是最容易被砍、也最容易在试点第一天暴露的一项。

## 32.3 采购清单

### 硬件

| 项 | 用途 | 数量 | 备注 |
| --- | --- | --- | --- |
| 真机池 | 兼容测试 | 17 台 | 见 31 章 S18 选型 |
| 边缘网关 | 老设备接入、离线续会 | 试点 3 台起 | 需 RS-485/232/红外/GPIO |
| HDMI 采集卡 | L3 硬件采集 | 4 套 | 支持 1080p60 |
| 白板 | 手写与触控验证 | 2 台 | 不同厂商 |
| 一体机／TV | 大屏验证 | 各 2 | 不同屏参 |
| 加密机 / HSM | KEK 托管 | 1 台或云 HSM | 涉密必买硬件 |
| 国产化终端 | 麒麟/统信/ARM64 验证 | 2 台 | 政企项目必需 |
| 备用终端 | 现场换机 | 按会议室 5% | 故障时不能等快递 |

### 软件与服务

| 项 | 用途 | 备注 |
| --- | --- | --- |
| 代码签名证书 | Windows/macOS 分发 | 无签名安装时会被拦 |
| Apple / 微软开发者账号 | 打包与上架 | 企业内分发也需 |
| TSA 时间戳服务 | 司法可信时间戳 | 国家授时中心只可用于校时，不签发 |
| ASR 服务 | 会议转写 | 自建或采购，按小时计费 |
| 短信／邮件通道 | 邀请与告警 | 需企业资质 |
| 商用字体授权 | UI 与文档 | 思源系列可商用，微软雅黑不可随产品分发 |
| 图库／图标／音效授权 | 界面素材 | 留存授权证明 |

字体是常被忽略的一项：把系统字体打进安装包对外分发，属于侵权风险，不是小事。

## 32.4 资质与合规

| 项 | 何时需要 | 周期 | 不做会怎样 |
| --- | --- | --- | --- |
| 域名 + ICP 备案 | 上线前 | 2–4 周 | 境内无法解析 |
| 等保 2.0 二级／三级 | 政企、医院、学校 | 1–3 个月 | 无法过立项与验收 |
| 商用密码应用安全性评估 | 涉密或要求国密 | 2–3 个月 | 密评不过不能上线 |
| 软件著作权 | 投标常要求 | 1–2 个月 | 投标被卡 |
| 个人信息处理合规 | 涉及师生、患者数据 | 贯穿 | 学校场景涉及未成年人，需监护人同意与最小化采集 |
| 数据出境评估 | 有境外访问 | 视情况 | 违规传输 |
| 视频／录音告知同意 | 录播与 AI 总结 | 贯穿 | 会议录音未告知即侵权 |

最后两条最容易被工程侧忽略：**录播与 AI 总结必须有会前告知与同意机制**，这不是产品选项，是合规前提。

## 32.5 第三方依赖（都要有替代方案）

| 依赖 | 用途 | 断供风险 | 替代 |
| --- | --- | --- | --- |
| PostgreSQL | 元数据 | 低 | 国产库（需评估 SQL 兼容） |
| NATS JetStream | 事件总线 | 中 | Redis Streams（能力有损） |
| OpenSearch | 检索 | 中 | 国产检索或 ES |
| MinIO | 对象存储 | 低 | 本地文件系统 + 自研分片 |
| EMQX | MQTT | 中 | 自研 MQTT Broker |
| ASR | 转写 | 高 | 本地模型，准确率下降可接受 |
| HSM | 密钥 | 高 | 软 KMS + 分片保管（安全性下降，需书面告知） |

**任何第三方都要在 ADR 里写清「断供怎么办」**。没写替代方案的依赖，等于把交付日期交给别人。

## 32.6 工具链

| 类别 | 建议 | 说明 |
| --- | --- | --- |
| 代码托管 | 自建 GitLab 或 GitHub 企业版 | 政企项目常要求内网自建 |
| CI Runner | 自托管，含 macOS 与 ARM64 | 三平台打包必需 |
| 镜像仓库 | Harbor | 需支持签名与扫描 |
| 制品库 | Nexus | 存安装包与 SBOM |
| 缺陷跟踪 | Jira／禅道 | 与 26 章变更单打通 |
| 文档 | 本套 Markdown + 版本库 | 与代码同仓，改文档走 PR |
| 真机管理 | 设备农场或人工台账 | 17 台必须有人登记状态 |
| 压测 | k6 或自研脚本 | 需支持 20000 连接的场景 |
| 监控 | Prometheus + Grafana + 日志聚合 | 告警必须能到人 |

## 32.7 数据与素材

| 素材 | 用途 | 数量要求 |
| --- | --- | --- |
| 20 种格式样本库 | 转帧与兼容测试 | 每种 ≥5 个，含损坏样本 |
| 大文件样本 | 性能测试 | 300 页 PPT、200 MB Excel |
| 脱敏病历／成绩样本 | 行业演示 | 必须彻底脱敏，不得用真实数据 |
| 演示租户 | 售前与培训 | 3 个组织、200 用户 |
| 图标 / 插画 / 音效 | UI | 授权齐全 |

样本库要**版本化保存**，否则半年后无法复现「那个 PDF 为什么转帧失败」。

## 32.8 时间与钱

| 项 | 估算 | 口径 |
| --- | --- | --- |
| 研发 | 87 人月 | 18 章分模块估算 |
| 人月成本 | 2.5–5 万元 | 一线城市自研团队，含社保与管理分摊 |
| 研发总额 | 220–440 万元 | 不含采购与认证 |
| 一次性采购 | 25–60 万元 | 真机池、网关、HSM、采集卡 |
| 认证与测评 | 15–40 万元 | 等保 + 密评 + 软著 + 渗透 |
| 年度基础设施 | 8–30 万元 | 按三档部署差异 |
| 首版周期 | 8 人 × 11 个月 | 完整形态约 20 个月 |

以上为**区间估算，不是报价**。真实数字取决于四个未决口径（会议室规模、是否涉密、视频路线、客户数量），口径一变总价可能差 2–3 倍。

### 阶段可交付（每阶段都能单独卖或单独验）

| 阶段 | 内容 | 周期 | 可验证的结果 |
| --- | --- | --- | --- |
| P0-a | 内核 + 身份 + 会议 + 同屏 | 3 个月 | 10 个房间能开会、能翻页 |
| P0-b | 材料 + 批注 + 表决 + 纪要 | 2 个月 | 一场完整会议闭环 |
| P1-a | 六端 + 投屏 + 老设备 | 3 个月 | 一个真实会议室跑通 |
| P1-b | 检索 + 审计 + 安全 + 集群 | 3 个月 | 通过等保预检 |
| P2-a | 行业模板 + 集成 + 视频/AI | 3 个月 | 医院或学校试点 |
| P2-b | 联盟 + 运维体系 + 认证 | 按需 | 可对外交付 |

## 32.9 一个版本算「做完了」的清单

| # | 条件 | 判据 |
| --- | --- | --- |
| 1 | 功能 | P0 用例 100% 通过 |
| 2 | 门禁 | S01–S03 全绿，S04–S15 无 P1 |
| 3 | 性能 | 同步 P95、首屏、检索 P95 达标 |
| 4 | 安全 | 高危 0，越权矩阵通过 |
| 5 | 兼容 | 六端 + 17 台真机全覆盖 |
| 6 | 文档 | 设计、部署、运维、培训为当前版本 |
| 7 | 可回滚 | 演练过一次真实回滚 |
| 8 | 可运维 | 监控、告警、备份、值班已就位 |
| 9 | 合规 | 告知同意、脱敏、留痕机制在位 |
| 10 | 交付物 | 安装包、镜像、SBOM、许可证清单齐全 |

第 10 条常被漏：没有 SBOM 和许可证清单，客户安全审查过不了，交付就卡在最后一公里。

## 32.10 预算只有五分之一时砍什么

| 砍 | 理由 |
| --- | --- |
| 视频会议与 AI 总结 | 可对接既有会议系统，不影响核心价值 |
| 联盟与去中心化 | 单租户场景用不上 |
| 检索联邦（MySQL/多库） | 先做单库检索，够用 |
| 六端中的 TV 与一体机 | 先做 PC + 平板 + 网页 |
| 行业模板 | 先做一个行业，验证后再抽象 |

**不能砍的三样**：内核与同屏、安全与审计、离线预载。前两者是产品成立的前提，第三者是会议室现场的现实约束。

## 32.11 五个最可能卡住的点

| 卡点 | 表现 | 提前动作 |
| --- | --- | --- |
| 会议室网络 | 200 台终端连不上 AP | 勘察阶段出整改清单，写进合同责任 |
| 老设备协议 | 厂商不给文档 | 试点前拿到协议或采购旁路方案 |
| 等保／密评 | 整改项返工架构 | 设计阶段就按三级要求做，别等测评 |
| 签名与分发 | 客户端装不上、被拦 | 提前 2 个月办证书与账号 |
| TSA 与合作方 | 时间戳无效力 | 尽早对接有资质机构，别用校时代替 |

这五项的共同点：**都不在代码里，都无法靠加班解决**。项目延期通常不是写不出来，而是这五项在最后一刻才发现。
