# 27 成本与资源预算

## 27.1 成本结构

| 类别 | 内容 | 性质 |
| --- | --- | --- |
| 研发 | 人月投入 | 一次性 + 持续迭代 |
| 基础设施 | 服务器、带宽、存储、云资源 | 随规模线性增长 |
| 运营 | 部署、培训、值班、支持 | 半固定 |
| 合规 | 等保测评、密评、渗透测试 | 周期固定 |
| 变更 | 客户定制、行业适配 | 项目制 |
| 隐性 | 返工、故障、沟通 | 由质量决定 |

隐性成本最容易被漏算，也最容易失控：一次 P1 事故的代价通常等于一个月的研发投入。

## 27.2 研发成本估算

```
研发成本 = Σ(模块人月 × 人均月成本 × (1 + 管理系数))
管理系数 ≈ 0.15 ~ 0.25（含项目管理、评审、文档）
```

按第 18 章的 87 人月基准，若人均月成本为 C，则总研发成本约为 `87 × C × 1.2`。C 由当地薪资与社保公积金决定，此处不给具体数字，避免与真实报价脱节。

建议按模块单列，便于「砍范围」时算得清：砍掉 P2 的联盟节点（6 人月）能省多少，一目了然。

## 27.3 基础设施成本

| 档位 | 组成 | 成本驱动 |
| --- | --- | --- |
| 单机档 | 1 台 16 核 64 GB + 4 TB SSD | 硬件一次性 + 电费 |
| 标准档 | 3 应用 + 2 数据库 + 4 存储 + 3 中间件 | 服务器数量 × 单价 |
| 集群档 | 控制面 3 + 数据面 N × 区域 | 与租户数线性相关 |

云与自建的选择不看单价，看三件事：是否需要弹性峰值、是否有数据不出域要求、是否有运维人力。**没有运维人力的单位，自建一定比云贵**，因为故障成本被低估了。

带宽是隐藏大头：一场 200 终端、含视频的会议，峰值出口约 100 Mbps；若跨地域，回源流量费用常超过计算费用。

## 27.4 单场会议成本

| 项 | 计量 | 说明 |
| --- | --- | --- |
| 页帧存储 | 200 MB/场 | 生命周期内累计 |
| 录制 | 1.5 GB/小时 | 按重要会议开启 |
| ASR | 会议时长（分钟） | 按时长计费，普通话 |
| 摘要 | token 数 | 按输入+输出 token |
| 带宽 | 峰值 × 时长 | 视频会议的主要成本 |

控制手段三条：普通会议不做全量摘要（只做转写）；录制按「重要度」分级；页帧按 30 天热存储、之后转冷。

## 27.5 三年 TCO 模板

| 项 | 第 1 年 | 第 2 年 | 第 3 年 | 备注 |
| --- | --- | --- | --- | --- |
| 研发（含迭代） | 一次性为主 | 20% 维护 | 15% 维护 | 迭代按需求池 |
| 基础设施 | 部署 + 12 个月 | 12 个月 | 12 个月 | 按规模增长 30%/年 |
| 运营人力 | 1–2 人 | 1–2 人 | 2 人 | 值班 + 实施 |
| 合规测评 | 首次 | 年度复测 | 年度复测 | 按监管要求 |
| 变更与定制 | 按项目 | 按项目 | 按项目 | 走插件，不进内核 |

TCO 必须按「三年」算，不能只算首年采购。只看首年的方案，通常在第三年因运维与变更成本反超。

## 27.6 与纸质方案对比

纸质基线（100 人 / 月 30 场 / 每场 60 页）：

| 项 | 年成本构成 |
| --- | --- |
| 印制 | 页数 × 份数 × 单价 |
| 人力 | 分发、装订、回收，按工时折算 |
| 存储 | 纸质归档空间与保管 |
| 时效损失 | 改版重印、材料迟到 |

对比时只算「可量化」部分，不可量化的（决策效率、材料安全）单列说明，不要折算成钱——折算会削弱可信度。

回收期通常在 18–30 个月，取决于会议频次与材料页数。频次低、页数少的单位，回收期会超过设备寿命，此时应如实告知，而不是硬凑一个漂亮的数字。

## 27.7 成本优化杠杆

| 杠杆 | 效果 | 代价 |
| --- | --- | --- |
| 存储分层 | 冷数据成本降 60%+ | 取回延迟 |
| 边缘缓存 | 出口带宽降 90% | 网关硬件 |
| 录制分级 | 存储降 50% | 部分会议无回放 |
| ASR 分级 | AI 成本降 60% | 摘要粒度粗 |
| 页帧按需转 | 转帧算力降 30% | 首次打开稍慢 |
| 多租户共池 | 资源利用率升 | 隔离复杂度 |

优化要算「净收益」，不要只看单项降幅。例如录制分级省了存储，但可能引发客户投诉，隐性成本更高。

## 27.8 预算控制

| 机制 | 做法 |
| --- | --- |
| 归集 | 成本按租户/项目归集，可查「这个客户花了多少」 |
| 预警 | 月度支出超预算 10% 告警 |
| 审批 | 单笔超阈支出需审批 |
| 复盘 | 季度对比预算与实际，偏差入台账 |

没有归集的成本管理，最后都会变成「年底发现超了，但不知道超在哪」。

## 27.9 报价逻辑

报价不由成本单方面决定，三者取交集：成本（不能亏）、竞品（不能离谱）、客户价值（愿付多少）。

| 报价构成 | 说明 |
| --- | --- |
| 软件许可 | 按会议室数或按用户数 |
| 实施服务 | 按人日，含勘察、部署、培训 |
| 年度运维 | 按许可比例，含值班与升级 |
| 定制开发 | 按人日，明确不进内核 |

报价单必须写清「不含项」：老设备改造、网络改造、第三方系统接口开发、涉密测评费用。这些是最常见的争议来源。
