# 14 行业赋能与 DIY 交付

## 14.1 赋能的本质

「赋能」不是给每个行业做一套系统，而是**同一内核 + 行业模板包**。模板包包含四样东西：组织模型、会议流程、字段与界面、合规策略。换行业只换模板包，不动内核。

## 14.2 医院

| 维度 | 设计 |
| --- | --- |
| 典型会议 | 院务会、科室会、病例讨论、多学科会诊（MDT）、评审会 |
| 特殊需求 | 病历影像调阅、患者信息脱敏、会诊结论留痕、跨院区协作 |
| 关键能力组合 | 会议域 + 媒体域（会诊需视频）+ 知识域（病历检索）+ 治理域 |
| 合规 | 患者信息最小可见、诊断信息属敏感个人信息、留痕可追溯、不得外传 |
| 特殊控件 | DICOM 影像查看器（插件）、脱敏开关、会诊结论双签 |

三个容易踩的坑：

1. **影像不是图片**。DICOM 需要窗宽窗位调节与序列浏览，用普通图片渲染会丢失诊断信息。必须用影像插件，不能走通用页帧。
2. **脱敏要做在服务端**。客户端脱敏等于没脱敏，因为原始数据已经下发。
3. **会诊结论的双签**：主讲医师与上级医师分别签名，缺一不可，这是医疗质量要求而不是产品花样。

## 14.3 企业

| 维度 | 设计 |
| --- | --- |
| 典型会议 | 董事会、经营分析会、部门周会、项目评审、安全委员会 |
| 特殊需求 | 董事会决议归档、财务数据联动、跨部门/跨子公司协同、外部董事接入 |
| 关键能力组合 | 会议域 + 协作域 + 集成域（财务/ERP）+ 知识域 |
| 合规 | 董事会材料高密级、决议需签署、内幕信息管控（知情人名单） |
| 特殊控件 | 决议签署面板、财务凭证联动、知情人水印 |

企业的核心诉求是**决议闭环**：会议形成决议 → 转任务 → 跟踪 → 完成归档。平台把这一步做成标准流程，而不是让客户自己用表格追。

## 14.4 学校

| 维度 | 设计 |
| --- | --- |
| 典型会议 | 校务会、教研组会、年级组会、家长会、职称评审 |
| 特殊需求 | 教研资料共享、成绩数据脱敏、班级/年级隔离、家长只读 |
| 关键能力组合 | 会议域 + 协作域 + 知识域（教研资料库）+ 治理域 |
| 合规 | 未成年人信息保护、成绩属敏感信息、家长访问需授权且限时 |
| 特殊控件 | 成绩表脱敏视图、家长访客模式、教研组共享盘 |

学校的特殊点是**角色多而权限碎**：校长、中层、教师、家长、学生，五类角色的可见范围完全不同。平台用组织域树 + 角色模板一次配好，避免逐人授权。

## 14.5 DIY 交付引擎

「快速根据企业和学校做 DIY」靠三件工具：

| 工具 | 作用 | 产出 |
| --- | --- | --- |
| 行业模板包 | 预置组织模型、流程、字段、界面、策略 | 一个可导入的 `.tpl` 包 |
| 配置向导 | 五步问答式配置（规模/密级/终端/集成/合规） | 生成配置清单 |
| 一键初始化 | 按清单创建租户、组织、角色、策略、示例数据 | 可开会的环境（≤ 2 小时） |

五步向导的问题设计：

| 步 | 问题 | 影响 |
| --- | --- | --- |
| 1 规模 | 多少会议室、多少终端、峰值并发 | 决定部署档位与集群参数 |
| 2 密级 | 最高密级、是否涉密 | 决定加密强度与是否物理隔离 |
| 3 终端 | 有哪些类型、多少老设备 | 决定接入级别与网关数量 |
| 4 集成 | 是否有 OA/ERP/HIS/NAS | 决定插件清单 |
| 5 合规 | 等保级别、是否需密评、审计对接 | 决定安全策略与审计通道 |

配置清单示例（可作为交付物的一部分）：

```yaml
tenant: demo-hospital
industry: hospital
scale:
  rooms: 30
  endpoints: 600
  peakConcurrent: 200
security:
  level: 3
  classification: secret          # 非涉密但含敏感个人信息
  encryption: sm4
  watermark: dynamic
org:
  model: hospital                 # 院区-科室-病区 三级
terminals:
  pc: 120
  tablet: 300
  board: 20
  kiosk: 40
  web: 160
  legacy:
    l1: 30
    l3: 10
integrations:
  - his
  - pacs
  - oa
plugins:
  - dicom-viewer
  - desensitize
  - dual-sign
audit:
  external: true
  tsa: true
```

## 14.6 私有网页与小程序接入

企业常问「能不能把我们自己的系统嵌进去」。答案是能，但要走第 04 章的界面插件规范：声明 slot、iframe 沙箱、票据换取、消息契约、审计。三类典型接入：

| 系统 | 接入形态 | 注意 |
| --- | --- | --- |
| 企业门户 | 侧栏嵌入待办与通知 | 只读为主，避免双入口打架 |
| 报销/工单 | 会议内直接发起 | 需票据透传，禁止账号密码进 iframe |
| 党建/学习 | 独立入口页 | 内容合规由客户负责，平台只做容器 |

## 14.7 五步交付路径

| 步 | 内容 | 工期 |
| --- | --- | --- |
| 1 勘察 | 网络、终端、会议室、既有系统盘点 | 3 天 |
| 2 配置 | 模板包 + 向导生成清单 | 1 天 |
| 3 部署 | 安装、初始化、导入组织与用户 | 2 天 |
| 4 试点 | 3 场真实会议，修问题 | 5 天 |
| 5 推广 | 分批开通、培训、验收 | 按规模 |

总计：中小单位 2 周可上线，大型单位 6–8 周。这个节奏能否成立，取决于勘察是否扎实——勘察不足，后面全是返工。

## 14.8 行业模板的维护

模板包会随行业规则变化而更新（如医院等级评审要求变化）。平台用「模板版本 + 差异升级」管理：客户环境记录当前模板版本，升级时只应用差异，不覆盖客户自定义项。这条机制不做，三年后每个客户都是一套无法升级的孤本。
