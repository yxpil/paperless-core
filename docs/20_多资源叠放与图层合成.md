# 20 多资源叠放与图层合成

## 20.0 问题的实质

会议现场经常要同时呈现：PPT 主讲、Excel 数据佐证、视频片段、白板推演、批注标记。如果每个端各自决定「谁在上面、谁占多大、谁挡住谁」，结果必然是六端画面不一致、录制与现场不一致、投屏与本人看到的不一致。

所以「叠放」不是 UI 排版问题，而是**一个可广播、可回放、可跨端复现的图层模型**。本章定义这个模型：层级、布局模板、仲裁规则、特殊资源处理、降级顺序。

## 20.1 图层栈

从底到顶固定八层，任何端不得增删层级，只允许某层为空。

| 层 | 名称 | 内容 | 交互 | 说明 |
| --- | --- | --- | --- | --- |
| L0 | 背景 | 纯色/会场底图/品牌底 | 不可交互 | 统一深色底，避免投影偏色 |
| L1 | 主资源 | 当前主呈现对象（PPT/PDF/Excel/视频/白板） | 可交互（按类型） | 占屏 ≥ 60% |
| L2 | 次资源 | 画中画、分屏第二资源 | 有限交互 | 占屏 15–35% |
| L3 | 批注标记 | 高亮、笔迹、箭头、贴纸 | 可交互 | 锚定到资源坐标 |
| L4 | 指示 | 激光笔、光标、聚光 | 可交互 | 会中临时，不持久化 |
| L5 | 控件 | 工具条、页码、缩放、议程条 | 可交互 | 可自动隐藏 |
| L6 | 安全 | 水印、遮罩、密级角标、防截屏提示 | 不可交互 | **永远置顶**，任何布局不得覆盖 |
| L7 | 系统 | Toast、断网提示、熔断提示 | 不可交互 | 3 秒自动消失 |

三条硬规则：

1. **层职责单一**。批注层不得承载控件，控件层不得绘制水印。
2. **安全层不可被覆盖**。任何「全屏播放」「沉浸模式」都必须给 L6 留出绘制权。
3. **层级不跨越交互**。控件层的按钮不能被批注层拦截点击；这靠分层 canvas + DOM 事件分区保证。

## 20.2 五类资源的合成方式

不同类型的资源不能共用一种合成路径，这是叠放设计的核心难点。

| 资源 | 合成后端 | 为什么不能统一 |
| --- | --- | --- |
| PPT / PDF / 图片 | 页帧（位图纹理）+ Canvas | 内容固定，按页取图最省 |
| Excel / 大表格 | 虚拟网格控件（viewport 渲染） | 大表无法整页栅格化，且需滚动、冻结、选区 |
| 视频 | 独立视频 surface（video 元素 / 原生层） | 不能与 Canvas 同纹理合成，硬件解码路径独立 |
| 白板 | 矢量 Canvas 层 | 无限画布，需按视口重绘 |
| 第三方应用/网页 | 采集流（视频） | 无法解析内部结构，只能当画面 |

工程含义：**L1 与 L2 的合成器是「按资源类型选择后端」的策略模式**，不是单一渲染管线。视频层与位图层并存时，靠容器分层（DOM 层叠或原生视图叠层）而不是画到同一张画布。

## 20.3 布局模板

布局是数据，不是代码分支。模板决定 L1/L2 的矩形与层序，L3–L7 相对叠加。

| 模板 | 结构 | 典型用途 | 端适配 |
| --- | --- | --- | --- |
| `single` | 主资源 100% | 单页材料、PPT 主讲 | 全端 |
| `main-pip` | 主 75% + 画中画 25%（右下） | 材料 + 视频小窗 | PC/平板/网页/一体机 |
| `split-h` | 左右各 50% | PPT 与 Excel 对照 | PC/平板/网页 |
| `split-v` | 上下 60/40 | 材料 + 议程/备注 | PC/平板 |
| `grid-4` | 2×2 四分屏 | 多路视频、多材料比对 | 白板/TV/PC |
| `presenter` | 材料 65% + 备注 20% + 视频 15% | 演讲者视图（仅本人可见） | PC |
| `overlay-board` | 材料 100% + 白板透明覆盖 | 在材料上直接推演 | 白板/平板/PC |
| `tv-focus` | 主 100% + 角标 5% | 大屏只读 | TV |

`presenter` 是「私有不广播」的模板：它只影响本人视图，不改变房间 layout。这一点必须区分，否则主持人一开演讲者模式，全场都变成三栏。

## 20.4 布局的数据模型

```json
{
  "type": "room.layout.changed",
  "rev": 10251,
  "payload": {
    "layout": "main-pip",
    "slots": [
      { "slot": "primary", "source": { "kind": "material", "id": "mat-77", "page": 12 }, "rect": [0, 0, 0.75, 1], "z": 1 },
      { "slot": "secondary", "source": { "kind": "video", "id": "stream-3", "mode": "live" }, "rect": [0.77, 0.72, 0.22, 0.26], "z": 2 },
      { "slot": "annotation", "source": { "kind": "anno", "setId": "s-12" }, "z": 3 }
    ],
    "decidedBy": "u-host",
    "scope": "room"
  }
}
```

`rect` 用归一化坐标（0–1），保证六端在任何分辨率下等比一致。`z` 只允许 1–2 取值，不做任意层序，避免出现「谁在上」的无限争议。

`scope` 有两个值：`room`（广播，全场一致）与 `self`（仅本人，如演讲者视图）。这是解决「某人想放大看一眼」与「不能让全场跟着变」的矛盾的关键。

## 20.5 仲裁规则

| 场景 | 规则 |
| --- | --- |
| 主持人改布局 | 立即生效，广播 `room.layout.changed` |
| 联席主持改布局 | 需主持人授权段内生效，段外只读 |
| 普通参会人改布局 | 只写 `scope:self`，不影响他人 |
| 两人同时改 | 主持人优先；同级按 rev 顺序，后者被拒并提示 |
| 临时全屏 | 本人视图放大至 100%，退出后恢复房间布局 |
| 布局与材料翻页冲突 | 翻页只改 slot 内容，不改布局 |

一条容易被忽略的规则：**改布局不改状态机**。布局是「视图」，会议状态是「事实」。把布局塞进状态机会导致回放时无法重现当时的画面。

## 20.6 视频资源

视频是最特殊的一类，三件事必须单独设计。

**第一，播放同步。** 视频以服务端为播放锚点：`{videoId, startAt, offsetMs, rate}` 广播，各端按自己与服务端的时钟偏差换算本地播放位置。偏差 > 300 ms 时校准一次（跳帧或微调倍速），不频繁 seek。

**第二，冻结帧批注。** 想在视频画面上做标记，必须先「冻结」到某一帧，批注锚定为 `(videoId, timecode, x, y)`。恢复播放后批注暂时隐藏，回到该时间码再出现。直接画在流动画面上没有意义，因为帧已经过去了。

**第三，录制复用同一布局。** 录制合成器读取同一个 layout 描述生成画面，这样「现场看到的」与「回放看到的」结构一致。如果录制另写一套排版，必然出现「录制里没有画中画」这类事故。

| 场景 | 处理 |
| --- | --- |
| 视频为主 | `single` 模板，材料降为角标或隐藏 |
| 视频为辅 | `main-pip`，小窗可拖动但吸附到四角 |
| 多路视频 | 服务端合成 `grid-4` 下发（TV 与录制），或终端各自合成（PC） |
| 视频 + 材料 + 批注 | 批注层只在材料区域生效，视频区域批注需先冻结 |

## 20.7 Excel 与办公文档

Excel 与 PPT 的差别在于**它不是「页」，而是「视口」**。

| 项 | PPT/PDF | Excel |
| --- | --- | --- |
| 单元 | 页 | 单元格区域 |
| 同步对象 | 页号 | `sheet + range + zoom + frozen` |
| 渲染 | 页帧位图 | 虚拟网格 |
| 主讲人滚动 | 换页 | 换视口 |
| 跟随者 | 跟随页 | 跟随视口，可自行退出跟随 |
| 转页帧时机 | 上传即转 | 仅导出/归档时转 |

投屏 Excel 时，主讲人移动视口即广播 `sheet.viewport.changed`，跟随端同步滚动。允许参会人「退出跟随」自己看别的区域——这在数据核对场景里是刚需，但要在界面上标明「你已脱离主讲视图」。

PPT 的特殊点是**动画**。平台默认把动画渲染为最终态（避免各端动画不同步），需要动画时按「页内步骤」拆分为子页，主讲人逐步推进。这是取舍：牺牲部分动效，换取六端一致。

## 20.8 批注与白板的叠放

| 模式 | 行为 | 适用 |
| --- | --- | --- |
| 批注层（`annotate`） | 在材料上标注，锚定页坐标 | 审阅、讨论 |
| 透明白板（`overlay-board`） | 在材料上自由书写，材料不动 | 推演、讲解 |
| 独立白板（`standalone`） | 全屏白板，材料退出 | 头脑风暴 |

透明白板与批注层的区别在于「是否持久」。批注随版本保存并可检索；透明白板默认只存在于本次会议，会后可选导出为图片。

跨资源锚点规则：批注不跨资源迁移。材料从 PPT 换成 Excel，原批注留在 PPT 上，不跟随。想「跟着人走」的是讨论记录（纪要），不是批注。

## 20.9 性能与降级

每增加一层都有成本，必须知道钱花在哪。

| 配置 | 内存增量 | 说明 |
| --- | --- | --- |
| 单资源（页帧） | 基准 | — |
| + 批注层 | +15% | 独立 canvas |
| + 视频小窗 | +40%（含解码缓冲） | 独立 surface |
| + 第二页帧资源 | +25% | 纹理缓存 |
| 四分屏视频 | +120% | 不建议在平板上用 |

降级顺序（带宽/性能不足时从先到后）：关动画 → 关视频 → 降分辨率 → 关次资源 → 单资源。顺序的原则是**保信息，舍效果**：视频可以关，材料不能少。

移动端硬限制：同时最多 2 个资源层 + 1 个视频层。超出则强制 `main-pip`。

## 20.10 可读性约束

叠放不能以牺牲可读性为代价。

| 约束 | 数值 |
| --- | --- |
| 主资源最小占屏 | ≥ 60% |
| 次资源最小宽度 | ≥ 240 px（PC）/ 20%（TV） |
| 文本被遮挡比例 | 0（批注不得覆盖正文超过 10 秒） |
| 层间对比 | 次资源需 2 px 描边或投影区分 |
| TV 安全区 | 96 px，任何层不得进入 |

批注覆盖正文是最常见的体验问题：讲者画一笔盖住关键数字，全场看不见。平台在批注层做「半透明淡化」：停笔 5 秒后笔迹透明度降到 60%，鼠标移入恢复。

## 20.11 指标

| 指标 | 目标 |
| --- | --- |
| 布局广播到生效 | P95 ≤ 200 ms |
| 六端画面差异 | 像素差 < 0.5% |
| 视频同步偏差 | ≤ 300 ms |
| 切布局不闪黑 | 是（双缓冲） |
| 录制与现场一致性 | 结构一致 100% |

## 20.12 常见错误

| 错误 | 后果 | 正确做法 |
| --- | --- | --- |
| 每端各自排版 | 六端不一致，客户投诉 | 布局作为数据广播 |
| 把视频画进 canvas | 卡顿、无法硬解 | 独立 surface |
| Excel 当页帧翻 | 大表看不清、无法滚动 | 视口同步 |
| 批注层盖住控件 | 点不到按钮 | 分层事件分区 |
| 录制另写排版 | 回放与现场不一致 | 复用 layout 描述 |
| 全屏模式去掉水印 | 安全事故 | 安全层强制置顶 |
