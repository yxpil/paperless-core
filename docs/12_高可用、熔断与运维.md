# 12 高可用、熔断与运维

## 12.1 可用性目标

| 场景 | 目标 | 说明 |
| --- | --- | --- |
| 会议进行中 | 不允许整体不可用 | 单节点故障不影响在开的会 |
| 材料读取 | 99.95% | 年不可用 ≤ 4.4 小时 |
| 写入（批注/表决） | 99.9% | 可短暂排队但不丢 |
| 恢复 | RTO ≤ 30 分钟（服务）、RPO ≤ 5 分钟（数据） | 数据库 RTO 可放宽到 4 小时 |

## 12.2 集群模式

| 组件 | 扩展方式 | 一致性 | 单点风险 |
| --- | --- | --- | --- |
| api | 无状态水平扩 | 强（读写主库） | 无 |
| ws-gateway | 按连接数扩，房间粘性 | 会话态在 Redis | 单节点掉线，客户端重连 |
| sync-worker | 按 roomId 分片，主备成对 | 房间内单写者 | 分片主故障，备接管 |
| doc-worker | 队列驱动，按深度扩 | 任务幂等 | 无 |
| PostgreSQL | 主备流复制 | 强 | 主故障需切换 |
| Redis | 哨兵 / 集群 | 最终 | 哨兵自动切 |
| MinIO | 纠删码多节点 | 最终 | 多盘容错 |
| NATS | 3 节点集群 | 最终 | 集群自愈 |
| OpenSearch | 分片 + 副本 | 最终 | 副本接管 |

房间分片是关键设计：加节点不减房间，而是减「每节点的房间数」。分片用一致性哈希，节点增减只迁移部分房间，迁移期间该房间短暂进入「只读待迁移」状态（≤ 3 秒）。

## 12.3 熔断

平台做三级熔断，粒度不同，目的不同。

| 级别 | 对象 | 触发 | 动作 |
| --- | --- | --- | --- |
| L1 依赖熔断 | 单个外部依赖（ERP、HIS、NAS） | 连续失败 5 次或错误率 > 50% | 断开该依赖，30 秒半开试探 |
| L2 服务自适应 | 单个接口/插件 | P99 > 2 s 或队列深度超阈值 | 限流、降级到缓存结果 |
| L3 租户级熔断 | 一个租户/部门 | 危险感知评分 > 70 或资源超用 | 冻结高风险动作、限速 |

熔断器实现要点：状态机 `关闭 → 打开 → 半开`，半开只放 1 个请求试探，成功即恢复。熔断事件必须写审计，且带「谁触发的、依据什么指标」。

```ts
const breaker = new CircuitBreaker(callErp, {
  timeout: 3000,
  errorThresholdPercentage: 50,
  resetTimeout: 30000,
  volumeThreshold: 5,
  onOpen: (e) => audit.record('breaker.open', { dep: 'erp', reason: e.message }),
  onHalfOpen: () => audit.record('breaker.halfOpen', { dep: 'erp' }),
});
```

“自动熔断”不等于“自动放弃”：熔断期间平台必须提供降级路径（缓存、排队、只读），否则一次外部系统抖动就会让会议开不下去。

## 12.4 主备与脑裂

| 项 | 设计 |
| --- | --- |
| 复制 | PostgreSQL 流复制（同步或准同步），延迟阈值 10 秒 |
| 仲裁 | 3 节点见证（witness），避免双主 |
| 切换 | 自动（延迟超阈 + 主不可达）或手动，切换后 VIP 漂移 ≤ 10 秒 |
| 脑裂防护 | 主必须持有租约（lease），租约到期自动降级为只读 |
| 回切 | 原主恢复后作为备加入，禁止直接接管 |
| 演练 | 每季度一次，含「主库拔电」与「网络分区」两种 |

脑裂是最危险的状态：两个主同时接受写入，事后合并几乎不可能。因此租约机制不是可选项。

## 12.5 监控与告警

| 指标 | 阈值 | 级别 |
| --- | --- | --- |
| 服务 CPU | 持续 5 分钟 > 70% | 警告 |
| 内存 | > 80% 且持续增长 | 严重 |
| 同屏延迟 P95 | > 500 ms | 警告 |
| 长连接数 | > 容量 80% | 警告 |
| 转帧队列 | > 50 | 警告 |
| 5xx 比例 | > 1% | 严重 |
| 数据库复制延迟 | > 10 s | 严重 |
| 磁盘 | > 85% | 警告 |
| 备份任务 | 失败/超时 | 严重 |
| 熔断器打开数 | > 3 | 严重 |
| 审计推送积压 | > 1 小时 | 警告 |

告警必须带上下文（租户、房间、影响终端范围、最近变更）。只报「服务异常」的告警视为不合格。

## 12.6 备份

| 对象 | 方式 | 频率 | 保留 | RPO |
| --- | --- | --- | --- | --- |
| PostgreSQL | 全量 + WAL 归档 | 日全量 / 15 分钟归档 | 30 天 | 15 分钟 |
| 对象存储 | 桶复制到异地 | 实时 | 180 天 | ≤ 1 小时 |
| 配置与密钥 | 加密导出 + 分片 | 每次变更 | 长期 | 手工 |
| 审计链 | 冷备 + 时间戳锚 | 每月 | 长期 | 1 小时 |

**备份三大纪律**：不演练的备份不算备份；备份与生产不同域；备份介质不可被业务账号写入（防勒索加密）。

## 12.7 容量与扩容

扩容触发：连接数达 80%、同步延迟连续 10 分钟超阈、队列持续积压、CPU 持续 70%。
扩容顺序：ws-gateway → sync-worker → doc-worker → api → 数据库只读副本。
数据库写能力不足时，先优化慢查询与索引，不允许用升配掩盖设计问题。

## 12.8 发布与回滚

| 阶段 | 时长 | 判定 |
| --- | --- | --- |
| 灰度 5% | ≥ 30 分钟 | 错误率 < 0.5% |
| 放量 30% | ≥ 2 小时 | 错误率 < 0.5%，延迟无劣化 |
| 全量 | — | 观察 24 小时 |

回滚触发：错误率 > 1%、同步延迟超阈、任一 P1 缺陷。回滚以镜像版本回退为主，数据库向前兼容，不回退结构。

## 12.9 故障处置手册

| 现象 | 可能原因 | 排查顺序 | 处置 |
| --- | --- | --- | --- |
| 终端无法入会 | 证书过期、白名单未加、网关不通 | 证书有效期 → 台账 → 连通性 | 续期/补录/临时放行 |
| 同屏不同步 | rev 跳号、房间迁移、弱网 | 服务端 rev → 分片状态 → 丢包 | 触发 snapshot，重连 |
| 材料转帧卡住 | 转换器崩溃、磁盘满 | worker 日志 → 磁盘 → 内存 | 重启任务、清理、扩容 |
| 表决结果异常 | 重复提交、离线补传 | 明细唯一索引 → 来源标记 | 以明细重算 |
| 设备无响应 | 串口参数、总线、网关离线 | 网关状态 → 串口日志 | 修参数/换线 |
| 大面积 5xx | 依赖不可用、连接池耗尽、发布缺陷 | 依赖健康 → 连接池 → 变更 | 熔断/回滚 |
| 主库不可用 | 硬件、网络分区 | 复制状态 → 租约 → 仲裁 | 切换并回切准备 |
| 审计链断裂 | 磁盘满、时钟跳变 | 链校验 → 时间源 | 补锚、重新对齐 |

## 12.10 值班与 SLA

| 级别 | 定义 | 响应 | 恢复 |
| --- | --- | --- | --- |
| P1 | 会议无法进行 / 数据错误 / 安全事件 | 15 分钟 | 2 小时 |
| P2 | 主要功能不可用 | 30 分钟 | 8 小时 |
| P3 | 局部功能异常 | 4 小时 | 3 个工作日 |
| P4 | 体验问题 | 次工作日 | 下版本 |

值班采用「一线 + 二线 + 专家」三级，一线只做标准动作（重启、切换、扩容），二线做根因分析，专家处理内核与数据问题。所有处置动作必须记录到事件单，24 小时内出复盘。
