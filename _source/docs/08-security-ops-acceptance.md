# 1 安全合规

## 1.1 安全目标与定级

本系统承载会议材料，材料密级最高为秘密级，业务影响面涉及单位决策过程，按 GB/T 22240-2020 的定级方法，建议定级为第三级，并按 GB/T 22239-2019 第三级要求设计与测评。安全目标有四项：材料不被非授权访问、材料不被非授权外带、操作全程可追溯、系统在攻击下可存活并快速恢复。

## 1.2 安全域划分

表 1 安全域与访问规则

| 安全域 | 组成 | 允许的访问 | 禁止的访问 |
| 终端接入域 | 会议终端、平板、白板、网页端 | 仅访问负载均衡 443 | 直连数据库、直连对象存储 |
| 边缘接入域 | 会议室网关 | 出站访问中心 443 与 8883 | 任何入站连接 |
| 应用服务域 | api、ws-gateway、worker | 访问数据域与消息总线 | 直接暴露到终端域 |
| 数据域 | 数据库、缓存、对象存储、检索 | 仅应用服务域访问 | 终端域与运维域直连 |
| 运维管理域 | 堡垒机、监控、日志 | 经堡垒机跳转访问 | 直接登录业务主机 |
| 外部接入域 | 零信任网关、上级单位 | 仅开放接口 | 访问内部数据域 |

域间通过防火墙策略与网络 ACL 双重控制，策略以最小集配置，新增策略须走变更审批并记录有效期。

## 1.3 等保控制项映射

表 2 主要控制项与实现措施

| 控制项 | 要求要点 | 本系统实现 |
| 身份鉴别 | 双因子、登录失败处理、会话超时 | 管理端强制双因子，5 次失败锁定 30 分钟，会话 15 分钟无操作失效 |
| 访问控制 | 最小权限、职责分离 | RBAC 加 ABAC，角色互斥由服务端强制，授权默认拒绝 |
| 安全审计 | 覆盖重要操作、不可删除、留存不少于 6 个月 | 三类审计全量采集，应用账号无删除权限，留存 180 天以上 |
| 入侵防范 | 最小安装、漏洞管理、防恶意代码 | distroless 镜像、每月漏洞扫描、上传文件强制病毒扫描 |
| 恶意代码防范 | 上传与执行环节检测 | 上传即扫描，隔离区存放，扫描通过才进入转帧 |
| 数据完整性 | 传输与存储完整性校验 | TLS 1.3、SHA-256 指纹、关键数据 SM3 摘要 |
| 数据保密性 | 传输与存储加密 | 密级材料服务端加密存储，密钥托管于密码机 |
| 剩余信息保护 | 退出后清除鉴别信息与敏感数据 | 会话销毁、终端缓存清理、内存敏感区清零 |
| 个人信息保护 | 最小化采集、明示同意 | 仅采集姓名、工号、部门，签到时明示用途 |

## 1.4 密码应用

按 GB/T 39786-2021 要求，本系统在四个环节使用密码技术：身份鉴别使用 SM2 证书或数字签名；传输通道使用 SM2 双证书与 SM4 会话加密；数据存储使用 SM4 对密级材料加密；完整性校验使用 SM3 摘要。密码资源由密码机或加密卡提供，业务系统通过标准接口调用，私钥不出设备。密钥生命周期包含生成、分发、使用、轮换、销毁五个阶段，轮换周期为 1 年，销毁需双人操作并留痕。

## 1.5 终端侧安全

终端是材料外泄的主要风险点。措施分四层：显示层施加动态水印，水印含姓名、工号、终端编号、时间，位置随机偏移并在 30 秒内缓慢漂移；系统层在 PC 与平板客户端启用防截屏接口，Android 使用 FLAG_SECURE，Windows 使用显示亲和性设置；文件层禁止落地明文，缓存加密存储，会议结束后按密钥销毁；行为层记录复制、打印、导出尝试并审计。

需要如实说明边界：网页端运行在用户自控的浏览器中，无法从技术上完全阻止截屏与录屏，系统采取的是提高外泄成本与事后可追溯的策略。任何声称网页端可以彻底防截屏的说法都不成立，安全方案设计时不得以此为依据。

## 2.4 容器编排

小型部署（不超过 50 会议室）使用 docker compose 单机多容器，中型以上使用 Kubernetes。两种方式共用同一镜像与同一套环境变量契约，切换不改代码。

```yaml
services:
  api:
    image: registry.local/pls/api:1.0.0
    environment:
      NODE_ENV: production
      DB_URL: postgres://pls:${DB_PASSWORD}@pg:5432/pls
      REDIS_URL: redis://redis:6379/0
      NATS_URL: nats://nats:4222
      S3_ENDPOINT: http://minio:9000
      JWT_SECRET_FILE: /run/secrets/jwt
    secrets: [jwt]
    deploy:
      replicas: 3
      resources:
        limits: { cpus: "4", memory: 8g }
    healthcheck:
      test: ["CMD", "/app/healthcheck"]
      interval: 15s
      timeout: 3s
      retries: 3
```

Kubernetes 部署要点四条：使用 PodDisruptionBudget 保证滚动更新时可用副本不低于 2；ws-gateway 使用 hostNetwork 或 NodePort 以避免 SNAT 导致连接数异常；doc-worker 设置 CPU 限额避免转帧抢占；所有工作负载设置 readinessGate，就绪后才接入流量。

## 2.5 配置与密钥

配置分四级：镜像默认、环境变量、配置中心、数据库动态配置，优先级由低到高。密钥不进入镜像与仓库，通过 secret 挂载文件或密钥管理系统注入。国密私钥保存在密码机，业务侧只持有句柄与证书。每次配置变更必须记录变更单号，禁止直接编辑容器内文件。

# 3 运维

## 3.1 监控与告警

表 8 关键监控指标与阈值

| 指标 | 阈值 | 级别 | 处置 |
| 服务 CPU 使用率 | 持续 5 分钟超过 70% | 警告 | 扩容或排查热点 |
| 服务内存使用率 | 超过 80% 且持续增长 | 严重 | 排查泄漏，准备重启 |
| 同步延迟 P95 | 超过 500 毫秒 | 警告 | 检查网络与广播队列 |
| 长连接数 | 超过容量的 80% | 警告 | 扩容网关 |
| 转帧队列深度 | 超过 50 | 警告 | 扩容 worker |
| 接口 5xx 比例 | 超过 1% | 严重 | 回滚或降级 |
| 数据库复制延迟 | 超过 10 秒 | 严重 | 检查主库压力与网络 |
| 磁盘使用率 | 超过 85% | 警告 | 清理或扩容 |
| 备份任务 | 失败或超时 | 严重 | 立即人工介入 |

告警必须带上下文：受影响租户、会议室、终端范围与最近一次变更。只报“服务不可用”的告警视为不合格告警，需在演练中整改。

## 3.2 日志体系

日志分三类：应用日志（结构化 JSON，按服务与级别分流）、访问日志（负载均衡侧，保留 90 天）、审计日志（业务侧，保留 180 天以上）。日志集中采集至 Loki 或等效系统，按 traceId 串联。日志中禁止出现材料正文、个人证件号与密钥片段；确需记录材料信息时只记录 ID。

## 3.3 备份与恢复

表 9 备份策略

| 对象 | 方式 | 频率 | 保留 | 恢复目标 |
| PostgreSQL | 全量加 WAL 归档 | 每日全量，15 分钟归档 | 30 天 | RPO 15 分钟，RTO 4 小时 |
| 对象存储 | 桶复制到异地 | 实时或每小时 | 180 天 | RPO 1 小时 |
| 配置与密钥 | 加密导出 | 每次变更 | 长期 | 手工恢复 |
| 审计归档 | 冷备至异地 | 每月 | 长期 | 按需调阅 |

恢复演练每季度一次，演练必须包含“误删材料后的恢复”与“数据库主库损坏后的切换”两个场景，演练记录归档。未演练过的备份视为没有备份。

## 3.4 容量与扩容

扩容触发条件为三项任一满足：长连接数达到容量 80%、同步延迟 P95 连续 10 分钟超过 500 毫秒、转帧队列深度连续 10 分钟超过 50。扩容顺序为 ws-gateway、doc-worker、api、数据库只读副本。数据库写能力不足时优先优化慢查询与索引，不得直接升配掩盖问题。

## 3.5 发布与回滚

发布窗口安排在非会议时段，发布前必须确认未来 2 小时内无重要会议。发布流程为：冻结变更、备份、灰度 5%、观察 30 分钟、放量 30%、观察 2 小时、全量。回滚触发条件为错误率超过 1%、同步延迟超过阈值、出现 P1 缺陷。回滚以镜像版本回退为主，数据库变更采用向前兼容设计，回滚时不回退数据结构。

## 3.6 故障处置

表 10 常见故障处置

| 现象 | 可能原因 | 排查顺序 | 处置 |
| 终端无法入会 | 证书过期、白名单未加、网络不通 | 证书有效期、台账、网关连通性 | 续期或补录，必要时临时放行 |
| 同屏不同步 | rev 跳号、时钟偏差、弱网 | 服务端 rev、终端偏差、丢包率 | 触发补拉，弱网降级 |
| 材料转帧卡住 | 转换器崩溃、磁盘满、内存不足 | worker 日志、磁盘、内存 | 重启任务、清理、扩容 |
| 表决结果异常 | 重复提交、离线补传、权限错误 | 明细唯一索引、离线来源标记 | 以数据库明细重算 |
| 设备指令无响应 | 串口参数错误、总线故障、网关离线 | 网关状态、串口日志、总线电阻 | 修正参数或更换线缆 |
| 大面积 5xx | 依赖不可用、连接池耗尽、发布缺陷 | 依赖健康、连接池、最近变更 | 回滚或降级 |

## 3.7 服务级别

生产环境提供 7 × 24 小时值班，一级故障 30 分钟内响应，二级 2 小时，三级次工作日。年度可用性目标 99.9%，即年停机不超过 8.76 小时。可用性统计以负载均衡侧探测为准，排除计划内停机窗口，计划内停机须提前 3 个工作日通知。

## 4.3 性能测试

性能场景分三个：容量场景（500 场会议、20000 连接、持续 2 小时）、尖峰场景（10 分钟内 200 场会议同时开局）、长稳场景（单场会议 200 终端、连续 8 小时）。通过标准为错误率不超过 0.1%、同步延迟 P95 不超过 300 毫秒、CPU 峰值不超过 70%、内存无持续增长、无连接泄漏。

## 5.1 验收流程

验收分四步：功能验收按第 2 分册 P0 条目逐条执行；性能验收按第 4.3 节场景执行；安全验收按漏洞扫描、渗透测试、越权测试、审计完整性四项执行；试运行不少于 2 周，期间记录全部故障与处置。四步全部通过方可签署验收报告。
