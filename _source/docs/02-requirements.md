# 1 概述

## 1.1 编写目的

本册把第 1 分册确立的产品定位分解为可实现、可测试的需求条目。每条需求都有唯一编号、优先级和验收方式，开发不得以实现难度为由缩减范围，测试不得以无法测试为由跳过条目；确实无法实现或无法验证的条目，必须走需求变更流程并在基线中标注。

## 1.2 需求组织方式

功能需求按业务模块分组，编号格式为 FR-模块-序号；非功能需求按质量属性分组，编号格式为 NFR-类别-序号。优先级分三级：P0 为必须，缺一不可验收；P1 为应该，本期交付，允许下一版本完善但不得缺失入口；P2 为可以，作为增强项排期。

## 1.3 需求来源与约束

需求来源为三类：单位会议管理办法与保密规定、同类系统的使用反馈、本项目立项时确定的量化指标。凡是管理办法与保密规定提出的要求，优先级一律为 P0，不接受“体验优先”的折中。

## 2.2 角色互斥规则

系统管理员不得同时具备审计员角色；机要员与会议管理员可为同一人但需双人复核；主持人不可为自己维护表决权限；审计员不得删除审计数据。角色互斥在授权时由服务端强制校验，不依赖前端隐藏入口。

# 3 业务流程

## 3.1 主流程

主流程分为九个步骤，每一步都有明确的前置条件与系统响应，任何一步失败都必须停在可恢复状态，不允许出现“半开会”状态。

表 2 会议主流程

| 步骤 | 动作 | 前置条件 | 系统响应 |
| S1 | 创建会议 | 具备建会权限 | 生成会议实体，状态为草稿，分配房间号 |
| S2 | 编排议程 | 会议处于草稿 | 保存议程项与顺序，支持拖拽排序 |
| S3 | 上传材料 | 会议处于草稿或待开始 | 上传至对象存储，异步转页帧，生成版本 |
| S4 | 材料审签 | 材料已上传 | 机要员标注密级与可见范围，签审后锁定 |
| S5 | 设定参会与权限 | 议程与材料就绪 | 生成参会名单与授权矩阵，生成预载任务 |
| S6 | 推送预载 | 会议发布为待开始 | 各端拉取材料，回传预载回执，未达标的端在签到页提示 |
| S7 | 签到与开局 | 到达预定时间或主持人触发 | 记录签到，校验到会率，主持人确认后进入进行中 |
| S8 | 会中控制 | 会议处于进行中 | 同屏、批注、表决、临时材料、白板、设备控制 |
| S9 | 结束与归档 | 主持人结束 | 冻结过程数据，生成纪要初稿，材料转只读，触发缓存销毁 |

## 3.2 异常流程

异常流程必须显式定义，否则实施阶段必然出现争议。系统覆盖五类异常：材料转帧失败、终端预载失败、会中网络中断、主持人终端故障、表决过程中断。每类异常都有降级动作与责任人，具体处理见第 6 章用例与第 8 分册运维手册。

# 8 约束与假设

## 8.1 约束

系统必须部署在单位内网或专网，默认不接入互联网；服务端运行环境为 Linux，容器化交付；材料源文件必须保留在单位可控的存储内，不得使用公有云对象存储；终端必须能访问中心服务的 443 端口；会议室的无线网络必须支持 802.11ac 及以上并保证单终端下行不低于 4 Mbps。

## 8.2 假设

假设单位已有统一身份平台并可提供 LDAP 或 OAuth2 接口；假设会议室已具备显示设备与网络布线；假设参会人具备基本的触控操作能力；假设实施期间可进入会议室进行不少于 3 次现场调试。

# 9 验收标准

## 9.1 功能验收

功能验收以本册第 4 章的 P0 条目为范围，逐条执行用例，通过率必须为 100%。P1 条目通过率不低于 95%，未通过项须有书面处置意见。

## 9.2 性能验收

性能验收在试点会议室与压测环境分别执行。压测环境模拟 500 场会议、20000 条长连接、单场 200 终端，连续运行 2 小时，错误率不超过 0.1%，同屏同步 P95 不超过 300 毫秒，服务端 CPU 峰值不超过 70%，内存无持续增长。

## 9.3 安全验收

安全验收包含漏洞扫描、渗透测试、权限越权测试、审计完整性核验四项。高危漏洞必须为 0，中危漏洞须整改完毕或有 compensating control 说明；越权测试覆盖 10 类角色交叉访问，全部拦截。

## 9.4 交付验收

交付验收要求部署文档、运维手册、培训材料、本套 8 册文档齐全，试运行不少于 2 周且无 P1 级故障，运维交接记录完整。
