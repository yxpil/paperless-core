# 1 设计原则

## 1.1 会议场景优先

无纸化系统的界面不是通用办公应用的界面。会议室场景有三个硬约束：光线可能偏暗、观看距离可能超过 3 米、操作者可能是第一次使用。界面因此遵循三条原则：信息层级扁平，常用动作不超过两级；操作反馈即时，任何点击在 100 毫秒内必须有视觉响应；关键状态外显，跟随、脱会、离线、表决中必须有持续可见的状态标识。

## 1.2 一致性优先于个性化

六端共用一套设计令牌与组件库，差异只允许出现在密度、字号、输入方式与导航结构四个维度，不允许出现同一功能在不同端有不同颜色、不同图标语义或不同按钮顺序。一致性通过“令牌化 + 组件单一实现”强制，而不是靠设计评审口头约束。

## 1.3 克制表达

界面不使用渐变背景、装饰性插图与动效炫技。色彩只用于表达状态与层级，不使用大面积高饱和色块。所有装饰性元素必须能回答“它帮助用户完成什么判断”，回答不了即删除。

# 2 工程结构

## 2.1 仓库组织

前端与终端在同一个 Monorepo 中管理，共享包承担核心逻辑，应用包只承担壳与平台适配。共享包一旦被两个以上端引用即升级为公共包，禁止在应用内复制粘贴核心逻辑。

```text
apps/
├── desktop/      # PC 客户端（Electron 28）
├── tablet/       # 平板终端（Capacitor 6，Android/iOS）
├── aio/          # 一体机终端（Capacitor 6，Kiosk）
├── board/        # 白板终端（Canvas 笔迹引擎）
├── web/          # 网页端（管理端 + 列席端）
└── tv/           # TV 大屏端（只读大屏）
packages/
├── design-tokens/  # 令牌：JSON 源 + CSS 变量 + TS 常量
├── ui-kit/         # 组件库（React 18 + 无样式内核）
├── render-core/    # 页帧渲染、批注图层、缩放与预加载
├── sync-client/    # 会话协议客户端（重连、补拉、去重）
└── platform/       # 端能力探测与平台适配接口
```

## 2.2 技术栈

表 1 前端技术栈

| 项目 | 选型 | 说明 |
| 框架 | React 18.3 | 六端统一，生态成熟 |
| 构建 | Vite 5 | 增量构建快，支持多端差异化配置 |
| 语言 | TypeScript 5.6 | 严格模式，禁止 any |
| 状态 | Zustand + 自研会话机 | 会话状态用有限状态机，避免布尔标志散落 |
| 样式 | CSS 变量 + CSS Modules | 令牌注入，避免运行时样式计算开销 |
| 渲染 | Canvas 2D 为主，WebGL 可选 | 页帧渲染与笔迹绘制 |
| 桌面壳 | Electron 28 | 双屏、系统水印、文件系统访问 |
| 移动壳 | Capacitor 6 | 复用 Web 内核，原生能力按需桥接 |

## 2.3 渲染内核

render-core 负责把服务端页帧画到屏幕上，并管理批注图层。核心接口固定为五个方法，六端实现差异只在参数。

```typescript
export interface RenderCore {
  mount(el: HTMLElement, opts: MountOptions): void;
  setDocument(doc: DocumentRef, page: number): Promise<void>;
  setViewport(vp: Viewport): void;              // 页码、缩放、滚动
  applyOps(ops: AnnotationOp[]): void;          // 批注增量，幂等
  snapshot(): Promise<Blob>;                    // 导出当前画面
}
```

渲染策略：每页预渲染到离屏画布，视口变化只做合成；相邻页预加载 2 页，翻页时复用缓存；缩放采用分级（0.5、0.75、1、1.5、2、3），非整数缩放由最近档位重采样，避免逐帧重绘。内存上限按端设定，超过上限按最久未使用淘汰。

# 3 设计令牌

## 3.1 令牌结构

令牌是设计与代码之间的唯一契约。所有颜色、间距、字号、圆角、阴影、动效必须引用令牌，禁止在组件中写魔法值。令牌源为 JSON，构建时生成 CSS 变量与 TypeScript 常量，六端共用。

```json
{
  "color": {
    "brand": { "base": "#1B4C7E", "hover": "#245D96", "active": "#12365C", "subtle": "#EAF0F6" },
    "semantic": { "success": "#2E7D32", "warning": "#B27C15", "danger": "#C0392B", "info": "#1B6FA8" },
    "neutral": { "n900": "#1F2328", "n700": "#4A5158", "n500": "#7A828B", "n300": "#C7CDD3", "n100": "#EEF1F4", "n0": "#FFFFFF" },
    "surface": { "page": "#F7F8FA", "card": "#FFFFFF", "overlay": "rgba(15,20,26,0.45)" }
  },
  "space": { "s1": 4, "s2": 8, "s3": 12, "s4": 16, "s5": 24, "s6": 32, "s7": 48 },
  "radius": { "sm": 4, "md": 8, "lg": 12, "pill": 999 },
  "font": {
    "family": { "zh": "Source Han Sans SC", "en": "Inter", "mono": "JetBrains Mono" },
    "size": { "caption": 12, "body": 14, "bodyLg": 16, "title": 20, "display": 32 }
  },
  "motion": { "fast": 150, "base": 200, "slow": 300, "easing": "cubic-bezier(0.2,0,0,1)" }
}
```

## 3.2 色彩使用规则

主色用于主要按钮、选中态、链接与关键标识；语义色只用于状态，不用于装饰；中性色承担文字与背景，正文文字必须使用 n900 或 n700，辅助文字使用 n500，浅色文字仅在深色背景上使用。任何前景与背景的对比度不得低于 4.5:1，大字号（不小于 24 像素）不得低于 3:1。

表 2 语义色用途

| 令牌 | 色值 | 用途 | 禁止用途 |
| brand.base | #1B4C7E | 主按钮、选中、链接 | 大面积背景 |
| success | #2E7D32 | 已完成、在线、通过 | 装饰性标记 |
| warning | #B27C15 | 即将超时、需注意 | 普通提示 |
| danger | #C0392B | 错误、离线、未通过 | 强调重点 |
| info | #1B6FA8 | 提示、说明 | 主按钮替代 |

## 3.3 暗色模式

会议场景常在暗光环境使用，六端均支持暗色模式。暗色下背景为 #12161B，卡片为 #1B2026，正文为 #E6E9EC，主色提亮为 #4A86C8 以保证对比度。暗色模式不改变信息层级与组件结构，只替换颜色令牌，禁止为暗色单独维护一套布局。

# 4 栅格与布局

## 4.1 栅格系统

基准单位为 4 像素，常用间距为 8、12、16、24、32。页面采用 12 列栅格，列间距 16 像素，页面左右安全边距按端设定。所有组件尺寸必须是 4 的整数倍，允许 1 像素的描边修正。

表 3 六端页面参数

| 端 | 基准宽度 | 安全边距 | 栅格列 | 基准字号 | 触控热区 |
| PC | 1440 | 24 | 12 | 14 | 32（鼠标） |
| 平板 | 1024 竖屏 / 1280 横屏 | 20 | 8 | 15 | 48 |
| 一体机 | 1920 | 24 | 12 | 16 | 56 |
| 白板 | 3840 | 32 | 12 | 18 | 64 |
| 网页 | 1280 及以上 | 24 | 12 | 14 | 40 |
| TV | 1920 | 96（5% 安全区） | 12 | 32 | 不适用 |

## 4.2 布局骨架

六端共用三段式骨架：顶部状态条（会议名称、时间、倒计时、连接状态、当前用户）、主内容区（材料、议程、白板）、底部工具条（翻页、批注、跟随、更多）。状态条与工具条在 TV 端自动隐藏并在遥控操作时浮出，在平板端折叠为图标，在 PC 端常驻。

# 5 字体与排版

## 5.1 字体族

中文使用思源黑体，西文使用 Inter，等宽场景使用 JetBrains Mono。字体文件随安装包分发，不依赖系统字体，避免不同终端渲染差异。字重只用 Regular 与 Medium 两档，标题不使用 Bold 以外的强调方式，避免小字号加粗导致笔画粘连。

## 5.2 字号与行高

表 4 字号阶梯与用途

| 令牌 | 字号 | 行高 | 用途 |
| caption | 12 | 18 | 辅助说明、时间戳、表格注释 |
| body | 14 | 22 | 正文、列表、表单 |
| bodyLg | 16 | 24 | 平板与一体机正文 |
| title | 20 | 28 | 卡片标题、对话框标题 |
| display | 32 | 40 | TV 端标题、大屏数据 |
| displayXl | 48 | 56 | TV 端会议名称、表决结果 |

## 5.3 文本规则

材料页为图片帧，不参与排版，界面文本必须遵守三条规则：单行不超过 32 个汉字（平板竖屏不超过 20 个）；数字与中文之间保留四分之一个空格；标题不使用句号，正文段落不使用省略号收尾。时间统一使用 24 小时制，日期使用“2026-11-05”格式，跨时区显示时在末尾标注时区。

## 6.3 组件实现约束

组件必须无状态受控，不自行发起网络请求；组件不得内置业务文案，文案通过属性传入，便于国际化与术语统一；组件必须支持键盘导航与焦点可见；组件必须有 Storybook 用例，覆盖全部状态；组件不得依赖端特有 API，端能力通过注入的 platform 接口访问。

# 7 六端适配

## 7.1 适配策略

适配不是缩放，而是重新组织信息密度与操作路径。PC 端追求效率，允许信息密集；平板与一体机追求可点，减少同时呈现的元素；白板追求可写，工具栏外置；网页端追求轻量，减少功能入口；TV 端追求可读，只呈现结论。

表 7 六端适配矩阵

| 维度 | PC | 平板 | 一体机 | 白板 | 网页 | TV |
| 导航 | 侧边栏 + 顶栏 | 底部标签 | 顶栏 + 大图标 | 侧栏工具 | 顶栏 | 无导航 |
| 密度 | 高 | 中 | 中 | 低 | 中 | 极低 |
| 输入 | 鼠标键盘 | 触控 | 触控 | 触控笔 | 鼠标 | 遥控 |
| 字号基准 | 14 | 15 | 16 | 18 | 14 | 32 |
| 列表行高 | 40 | 56 | 64 | 72 | 44 | 96 |
| 二次确认 | 仅危险操作 | 危险操作 | 危险操作 | 清空操作 | 危险操作 | 不适用 |
| 离线能力 | 完整 | 完整 | 完整 | 完整 | 降级 | 无 |

## 7.2 关键交互规范

同屏跟随：从端顶部常驻“跟随中”标识，标识包含主讲人姓名；用户手动翻页即视为脱会，标识变为“已脱会，点击回归”；主持人切换页面时，脱会终端不强制跳转，但显示“主讲人已翻至第 N 页”的提示条。这一设计避免了从端阅读被打断，也保证了状态可感知。

批注：进入批注模式必须有一次明确的模式切换反馈（工具条浮出且光标形态变化），退出批注不自动保存提示，笔迹实时提交并在 200 毫秒内可见。撤销只撤销本人最近一笔，撤销按钮长按可连续撤销。

表决：表决面板出现时锁定其他操作 3 秒，防止误触；提交后按钮变为“已提交”并显示提交时间；倒计时最后 10 秒数字变为警告色并每秒轻微缩放一次，不使用声音提醒，避免会议场合干扰。

防误触：一体机与平板的所有破坏性操作（结束会议、清空白板、撤回材料）需要二次确认，确认弹窗必须显示影响范围与不可恢复提示。

## 7.3 TV 端专项规范

TV 端观看距离通常为 4 至 8 米，因此只呈现三类信息：会议基本信息、当前材料页、表决结果。字号不小于 32 像素，正文对比度不低于 7:1，页面四周保留 5% 安全区，禁止把关键信息放在边缘 96 像素内。TV 端不显示鼠标指针、不显示滚动条、不显示技术性错误码，错误统一转为“请稍候，正在重连”。

# 8 动效与反馈

动效只承担三类功能：状态变化的空间关系（如面板滑出）、操作的因果反馈（如按钮按下）、加载的进度感知。时长规范为 150 毫秒用于微交互、200 毫秒用于面板展开、300 毫秒用于页面切换；缓动统一为 cubic-bezier(0.2,0,0,1)。禁止使用弹跳、旋转、闪烁类动效，禁止超过 400 毫秒的过渡，禁止在笔迹绘制路径上加入任何动画延迟。

加载反馈分三级：小于 200 毫秒不显示加载态；200 毫秒至 1 秒显示骨架屏；超过 1 秒显示进度并给出可取消入口。错误反馈必须包含三要素：发生了什么、影响是什么、用户可以做什么。

# 9 无障碍与可用性

界面必须满足四项基本要求：所有功能可通过键盘完成；焦点框清晰可见且不被裁切；所有图标按钮有可读标签；色彩不是唯一的信息载体（状态同时用文字或形状表达）。触控热区在平板与一体机不小于 48 像素，白板不小于 64 像素，相邻热区间距不小于 8 像素。

# 11 前端代码规范

## 11.1 状态管理

会话状态使用有限状态机表达，状态集合固定为 idle、joining、following、detached、offline、closing，禁止用多个布尔标志组合表达状态。状态迁移函数集中在一处，迁移必须记录原因，便于排查“为什么终端脱会”。

```typescript
export type SessionState = 'idle' | 'joining' | 'following' | 'detached' | 'offline' | 'closing';

const transitions: Record<SessionState, Partial<Record<SessionEvent, SessionState>>> = {
  idle:      { JOIN: 'joining' },
  joining:   { READY: 'following', FAIL: 'idle' },
  following: { DETACH: 'detached', LOST: 'offline', CLOSE: 'closing' },
  detached:  { FOLLOW: 'following', LOST: 'offline', CLOSE: 'closing' },
  offline:   { RECONNECTED: 'joining', CLOSE: 'closing' },
  closing:   { CLOSED: 'idle' },
};
```

## 11.2 编码约定

组件文件与组件同名，一个文件一个导出组件；样式使用 CSS Modules，禁止全局样式污染；网络请求统一走 sync-client 与 api-client，禁止组件内直接 fetch；所有异步操作必须处理失败分支，禁止空 catch；所有定时器必须在组件卸载时清理；禁止在渲染函数中做重计算，必要时使用 memo 与 worker。

## 11.3 契约测试

六端与后端共用 packages/contracts 中的类型与事件常量。契约测试在 CI 中执行：后端启动 mock 服务并回放录制的事件流，六端依次断言渲染结果与状态迁移。任何一端修改事件字段而未更新契约，测试立即失败。

# 12 设计交付与走查

设计交付物包含三件：Figma 设计稿（按端分文件，共用组件库）、令牌变更记录、交互说明文档。走查分三次：设计稿走查确认令牌与组件使用合规；开发完成后走查确认实现与设计一致，允许 1 像素误差；上线前走查确认暗色模式、TV 端可读性与无障碍项。走查记录归档在项目文档库，未通过项不得发布。
