## ⚠️ 先读这段（免责声明）

1. **还在施工、还在调试。** 仓库里的文档、接口、表结构、图表、脚本都处于迭代状态，随时会改、会推翻、会重写。任何数字（人月、成本、用例数、容量）都是**估算口径**，不是承诺。
2. **这里只公开"工作流程"，不公开成品。** 本仓库的目的是展示一条完整的链路长什么样：
   `需求 → 设计 → 基线 → 编码 → 测试 → 治理 → 交付 → 成本/组织`
   以及这条链路上各个环节是怎么互相咬合、怎么互相卡住、怎么被产业链上下游拉动的。
3. **不是招标文件、不是报价单、不是验收依据。** 文档里出现的行业方案、成本模型、组织分工，均为**方法论演示**，请勿直接照搬用于投标、签约或对外承诺。
4. **没有可运行的代码。** 目前只有文档体系 + 文档生成/校验脚本（`_source/`）。产品代码、演示环境、部署包**均未包含**。
5. **随时大改，不另行通知。** 你可以看、可以提 issue、可以拿去当模板，但别指望现在能跑起来——真跑起来的那天会写在更新日志里。

## 源文件与再生成

`_source` 保留 Word 的可复现源：`_source/docs/*.md` 为正文源、`_source/images/*.png` 为插图、`build_docx.py` 为生成器、`make_diagrams.py` 为绘图脚本。

```powershell
python .\_source\make_diagrams.py     # 重新生成插图（基线 8 册用）
python .\_source\build_docx.py        # 重新生成基线 8 册 DOCX
python .\_source\build_docx_all.py    # 由 docs/ 生成全集 10 册 DOCX
python .\_source\build_book.py        # 由 docs/ 生成 34 章合订本（00 无纸化全集 合订本）
```

修改基线册正文请改 `_source/docs/*.md`，不要直接改 DOCX；修改扩展全集请改 `docs/*.md` 后重跑 `build_docx_all.py`。目录页码无需手工刷新：生成器（`build_docx.py` 的 `enable_update_fields()`）已为每册写入 `w:updateFields`，Word 打开时自动重算目录与页码（不支持域更新的查看器可全选按 F9）。

### 交付闸门（改动后全跑一遍，全绿才算一轮交付）

| 脚本 | 检查内容 | 通过标志 |
| --- | --- | --- |
| `_source/verify_all.py` | V1–V10 结构计数（表/H1/段/字），期望值与生成器同源 | `ALL_OK` |
| `_source/audit_refs.py` | md 侧交叉引用：下一章链、反引号引用、章号与节号引用、00 文档地图 | `AUDIT_OK` |
| `_source/verify_delivery.py` | docx 产物侧正文回归：页脚计数、相邻重复页脚、关键标记 | `ALL_PASS` |
| `_source/verify_numbers.py` | 跨章关键数字一致性：332 用例 / 21 集合 / 75 条需求 / 45 人月口径等 | `NUMBERS_OK` |

> 并发约定：跑 `build_docx_all.py` 前先确认 `docs/` 下无 `_merge_*.md` 残留（存在即他人正在构建）；跑完立即跑四道闸门。详见 `COLLABORATION.md`。
